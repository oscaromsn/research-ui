## 7. Resource Management

### Core Principle

**All resources requiring explicit lifecycle management (acquisition and cleanup) MUST be managed using Effect's resource management primitives: `Effect.acquireRelease`, `Scope`, or `Effect.ensuring`.**

**Rationale**: Manual resource management is error-prone and leads to resource leaks, especially when dealing with interruptions, failures, or complex control flow. Effect's resource management guarantees cleanup occurs under all circumstances—success, failure, or interruption—providing the same safety as try-finally blocks but with better composability and type safety.

### 7.1 Basic Resource Patterns

#### Effect.acquireRelease

The fundamental pattern for resource management. Guarantees that release runs even on failure or interruption:

```typescript
import { Effect } from "effect"

// ✅ Basic resource acquisition and release
const withDatabaseConnection = <A, E, R>(
  use: (connection: Connection) => Effect.Effect<A, E, R>
): Effect.Effect<A, E | DatabaseError, R> =>
  Effect.acquireRelease(
    // Acquire: Returns the resource
    Effect.gen(function* () {
      const config = yield* Config
      yield* Effect.log("Opening database connection")
      return yield* Effect.tryPromise({
        try: () => createConnection(config.database),
        catch: (error) => new DatabaseError({ 
          cause: error, 
          operation: "connect" 
        })
      })
    }),
    // Release: Cleanup function - ALWAYS runs
    (connection) =>
      Effect.gen(function* () {
        yield* Effect.log("Closing database connection")
        yield* Effect.sync(() => connection.close()).pipe(
          // CRITICAL: Don't fail on cleanup errors - log them
          Effect.catchAll((error) =>
            Effect.logError("Failed to close connection", { error })
          )
        )
      })
  ).pipe(
    Effect.flatMap(use)
  )

// Usage
const queryDatabase = (sql: string) =>
  withDatabaseConnection((conn) =>
    Effect.tryPromise({
      try: () => conn.query(sql),
      catch: (error) => new QueryError({ cause: error })
    })
  )
```

**Key Pattern**: The release function receives the acquired resource and runs even if `use` fails or is interrupted. Always catch errors in release functions to prevent propagating cleanup failures.

#### Scope

For more complex resource management, use `Scope` to manage multiple resources:

```typescript
import { Effect, Scope } from "effect"

// ✅ Scope-based resource management
const makeScopedService = Effect.gen(function* () {
  // Acquire resource within scope
  const connection = yield* Effect.acquireRelease(
    openConnection(),
    (conn) => Effect.sync(() => conn.close())
  )

  const cache = yield* Effect.acquireRelease(
    openCache(),
    (c) => Effect.sync(() => c.close())
  )

  return {
    query: (sql: string) => 
      Effect.tryPromise(() => connection.query(sql)),
    cached: (key: string) =>
      Effect.tryPromise(() => cache.get(key))
  } as const
})

// Create scoped effect
const program = Effect.scoped(
  Effect.gen(function* () {
    const service = yield* makeScopedService
    const result = yield* service.query("SELECT * FROM users")
    return result
  })
) // All resources automatically cleaned up here
```

**Scope Benefits**:

- Automatic cleanup of all acquired resources
- Resources cleaned up in reverse acquisition order
- Composable with other scoped effects
- Clear resource lifecycle boundaries

#### Effect.ensuring

The Effect equivalent of try-finally, guarantees cleanup runs:

```typescript
import { Effect } from "effect"

// ✅ Guaranteed cleanup with ensuring
const processWithCleanup = Effect.gen(function* () {
  // Setup
  const tempFile = yield* createTempFile()
  
  // Main work
  const result = yield* processFile(tempFile)
  
  return result
}).pipe(
  // Cleanup ALWAYS runs, even on interruption
  Effect.ensuring(
    Effect.gen(function* () {
      yield* Effect.log("Cleaning up temporary file")
      yield* deleteTempFile()
    })
  )
)

// Alternative: Use ensuring for side-effect cleanup
const operation = riskyOperation.pipe(
  Effect.ensuring(
    Effect.sync(() => {
      // Cleanup side effect
      cleanup()
    })
  )
)
```

**When to use ensuring vs acquireRelease**:

- Use `acquireRelease` when you need the acquired resource in your computation
- Use `ensuring` when you just need guaranteed cleanup

### 7.2 Resource Lifecycle

Understanding the lifecycle phases helps design proper resource management:

#### Acquisition Phase

```typescript
// ✅ Proper acquisition with error handling
const acquireConnection = Effect.gen(function* () {
  const config = yield* Config
  const logger = yield* Logger

  yield* logger.info("Acquiring database connection", {
    host: config.database.host,
    database: config.database.name
  })

  const connection = yield* Effect.tryPromise({
    try: async () => {
      const conn = await createConnection(config.database)
      // Verify connection is valid
      await conn.ping()
      return conn
    },
    catch: (error) => new DatabaseError({
      cause: error,
      operation: "acquire",
      context: { host: config.database.host }
    })
  })

  yield* logger.info("Connection acquired successfully")
  return connection
})
```

#### Usage Phase

```typescript
// ✅ Resource usage with proper error handling
const useConnection = (connection: Connection) =>
  Effect.gen(function* () {
    // Set connection options
    yield* Effect.tryPromise(() => 
      connection.setOptions({ timeout: 30000 })
    )

    // Perform operations
    const result = yield* Effect.tryPromise({
      try: () => connection.query("SELECT * FROM users"),
      catch: (error) => new QueryError({ cause: error })
    })

    return result
  }).pipe(
    // Add timeout to prevent hanging
    Effect.timeout("30 seconds"),
    Effect.catchTag("TimeoutException", (error) =>
      Effect.fail(new DatabaseError({ 
        cause: error, 
        operation: "query_timeout" 
      }))
    )
  )
```

#### Release Phase

```typescript
// ✅ Safe release with error handling and logging
const releaseConnection = (connection: Connection) =>
  Effect.gen(function* () {
    const logger = yield* Logger

    yield* logger.debug("Releasing connection", {
      connectionId: connection.id
    })

    // Attempt graceful close
    const closed = yield* Effect.tryPromise(() => 
      connection.close()
    ).pipe(
      Effect.timeout("5 seconds"),
      Effect.option // Convert to Option to handle failures gracefully
    )

    if (closed._tag === "None") {
      yield* logger.warning("Connection close timed out, forcing close")
      yield* Effect.sync(() => connection.forceClose())
    }

    yield* logger.debug("Connection released")
  }).pipe(
    // CRITICAL: Never fail in release - always succeed after logging
    Effect.catchAll((error) =>
      Effect.gen(function* () {
        yield* Effect.logError("Error during connection release", { error })
        // Force close as fallback
        yield* Effect.sync(() => connection.forceClose()).pipe(
          Effect.ignore // Ignore even this error
        )
      })
    )
  )
```

**Release Best Practices**:

- Never let release functions fail - catch and log all errors
- Include timeouts for cleanup operations
- Provide fallback cleanup mechanisms
- Log all cleanup failures for debugging
- Force cleanup as last resort

### 7.3 Advanced Resource Patterns

#### Resource Pools

Implement efficient resource pooling for expensive resources:

```typescript
import { Effect, Semaphore, Ref, Queue } from "effect"

// ✅ Production-ready resource pool implementation
const makeResourcePool = <R>(options: {
  create: Effect.Effect<R, never, never>
  destroy: (resource: R) => Effect.Effect<void>
  validate: (resource: R) => Effect.Effect<boolean>
  size: number
  acquireTimeout?: Duration.DurationInput
}) =>
  Effect.gen(function* () {
    const { create, destroy, validate, size, acquireTimeout } = options

    // Available resources queue
    const available = yield* Queue.bounded<R>(size)
    
    // Track total resources
    const count = yield* Ref.make(0)
    
    // Semaphore for pool size limit
    const semaphore = yield* Semaphore.make(size)

    // Initialize pool
    yield* Effect.forEach(
      Array.from({ length: size }, (_, i) => i),
      () => Effect.gen(function* () {
        const resource = yield* create
        yield* Queue.offer(available, resource)
        yield* Ref.update(count, n => n + 1)
      }),
      { concurrency: "unbounded" }
    )

    const acquire = Effect.gen(function* () {
      // Get resource from pool
      const resource = yield* Queue.take(available).pipe(
        acquireTimeout 
          ? Effect.timeout(acquireTimeout)
          : Effect.identity
      )

      // Validate resource
      const isValid = yield* validate(resource)
      
      if (!isValid) {
        // Resource is invalid, create new one
        yield* destroy(resource).pipe(Effect.ignore)
        yield* Ref.update(count, n => n - 1)
        
        const newResource = yield* create
        yield* Ref.update(count, n => n + 1)
        return newResource
      }

      return resource
    })

    const release = (resource: R) =>
      Effect.gen(function* () {
        // Validate before returning to pool
        const isValid = yield* validate(resource)
        
        if (isValid) {
          yield* Queue.offer(available, resource)
        } else {
          // Replace invalid resource
          yield* destroy(resource).pipe(Effect.ignore)
          yield* Ref.update(count, n => n - 1)
          
          const newResource = yield* create
          yield* Queue.offer(available, newResource)
        }
      }).pipe(
        Effect.catchAll((error) =>
          Effect.logError("Error releasing resource to pool", { error })
        )
      )

    const withResource = <A, E>(
      use: (resource: R) => Effect.Effect<A, E>
    ): Effect.Effect<A, E> =>
      Effect.acquireRelease(
        acquire,
        release
      ).pipe(
        Effect.flatMap(use)
      )

    const shutdown = Effect.gen(function* () {
      yield* Effect.log("Shutting down resource pool")
      
      // Drain all resources
      const resources: R[] = []
      while (true) {
        const resource = yield* Queue.poll(available).pipe(Effect.option)
        if (resource._tag === "None") break
        resources.push(resource.value)
      }

      // Destroy all resources
      yield* Effect.forEach(
        resources,
        destroy,
        { concurrency: "unbounded" }
      ).pipe(Effect.ignore)

      yield* Effect.log("Resource pool shutdown complete")
    })

    return {
      withResource,
      shutdown,
      size: Ref.get(count)
    } as const
  })

// Usage example
const program = Effect.gen(function* () {
  const pool = yield* makeResourcePool({
    create: createDatabaseConnection(),
    destroy: (conn) => Effect.sync(() => conn.close()),
    validate: (conn) => Effect.tryPromise(() => conn.ping()),
    size: 10,
    acquireTimeout: "5 seconds"
  })

  // Use pool
  yield* pool.withResource((conn) =>
    Effect.tryPromise(() => conn.query("SELECT * FROM users"))
  )

  // Cleanup
  yield* pool.shutdown
})
```

#### Nested Resources

Manage multiple dependent resources properly:

```typescript
// ✅ Nested resource management
const withDatabaseAndCache = <A, E, R>(
  use: (db: Database, cache: Cache) => Effect.Effect<A, E, R>
): Effect.Effect<A, E | DatabaseError | CacheError, R> =>
  Effect.acquireRelease(
    openDatabase(),
    (db) => closeDatabase(db)
  ).pipe(
    Effect.flatMap((db) =>
      Effect.acquireRelease(
        openCache(),
        (cache) => closeCache(cache)
      ).pipe(
        Effect.flatMap((cache) => use(db, cache))
      )
    )
  )

// Alternative: Using Effect.all for parallel resource acquisition
const withParallelResources = <A, E, R>(
  use: (resources: { db: Database; cache: Cache; logger: Logger }) => 
    Effect.Effect<A, E, R>
): Effect.Effect<A, E | ResourceError, R> =>
  Effect.all({
    db: Effect.acquireRelease(
      openDatabase(),
      (db) => closeDatabase(db)
    ),
    cache: Effect.acquireRelease(
      openCache(),
      (cache) => closeCache(cache)
    ),
    logger: Effect.acquireRelease(
      createLogger(),
      (logger) => logger.flush()
    )
  }).pipe(
    Effect.flatMap(use)
  )
```

**Resource Cleanup Order**:

- Resources are cleaned up in **reverse** order of acquisition
- Inner resources (acquired later) are cleaned up first
- This ensures dependencies are available during cleanup

#### Conditional Resources

Handle optional or feature-flag-based resources:

```typescript
// ✅ Conditional resource acquisition
const withOptionalCache = <A, E, R>(
  useCache: boolean,
  use: (cache: Option.Option<Cache>) => Effect.Effect<A, E, R>
): Effect.Effect<A, E | CacheError, R> =>
  useCache
    ? Effect.acquireRelease(

      ).pipe(
        Effect.map(Option.some),
        Effect.flatMap(use)
      )
    : use(Option.none())

// Feature-flag based resources
const withFeatureResources = <A, E, R>(
  features: { enableMetrics: boolean; enableTracing: boolean },
  use: (resources: {
    metrics: Option.Option<MetricsCollector>
    tracing: Option.Option<TracingService>
  }) => Effect.Effect<A, E, R>
): Effect.Effect<A, E, R> =>
  Effect.gen(function* () {
    const metrics = features.enableMetrics
      ? Option.some(yield* Effect.acquireRelease(
          createMetricsCollector(),
          (m) => m.close()
        ))
      : Option.none()

    const tracing = features.enableTracing
      ? Option.some(yield* Effect.acquireRelease(
          createTracingService(),
          (t) => t.shutdown()
        ))
      : Option.none()

    return yield* use({ metrics, tracing })
  })
```

#### Resource Sharing

Share resources across multiple operations safely:

```typescript
// ✅ Shared resource pattern
const makeSharedConnection = Effect.gen(function* () {
  const connection = yield* Effect.acquireRelease(
    openConnection(),
    (conn) => closeConnection(conn)
  )

  const query = (sql: string) =>
    Effect.tryPromise({
      try: () => connection.query(sql),
      catch: (error) => new QueryError({ cause: error })
    })

  const transaction = <A, E>(
    work: Effect.Effect<A, E>
  ): Effect.Effect<A, E | DatabaseError> =>
    Effect.gen(function* () {
      yield* Effect.tryPromise(() => connection.beginTransaction())
      
      const result = yield* work.pipe(
        Effect.catchAll((error) =>
          Effect.gen(function* () {
            yield* Effect.tryPromise(() => connection.rollback()).pipe(
              Effect.ignore
            )
            return yield* Effect.fail(error)
          })
        )
      )

      yield* Effect.tryPromise(() => connection.commit())
      return result
    })

  return { query, transaction } as const
})

// Use in service
export const DatabaseServiceLive = Layer.scoped(
  DatabaseService,
  Effect.gen(function* () {
    const { query, transaction } = yield* makeSharedConnection
    
    return {
      findUser: (id: string) => query(`SELECT * FROM users WHERE id = '${id}'`),
      createUser: (user: NewUser) =>
        transaction(
          Effect.gen(function* () {
            yield* query(`INSERT INTO users ...`)
            yield* query(`INSERT INTO profiles ...`)
          })
        )
    } as const
  })
)
```

### 7.4 Resource Management in Services

#### Service-Level Resources

Services should manage their resources using `Layer.scoped`:

```typescript
import { Effect, Layer, Context } from "effect"

// ✅ Service with managed resources
class DatabaseService extends Context.Tag("DatabaseService")
  DatabaseService,
  {
    readonly query: (sql: string) => Effect.Effect<unknown[], QueryError>
    readonly transaction: <A, E>(
      work: Effect.Effect<A, E>
    ) => Effect.Effect<A, E | DatabaseError>
  }
>() {}

const makeDatabaseService = Effect.gen(function* () {
  const config = yield* Config
  const logger = yield* Logger

  // Resource is automatically managed by Layer.scoped
  const pool = yield* Effect.acquireRelease(
    Effect.gen(function* () {
      yield* logger.info("Creating database pool", {
        maxConnections: config.database.maxConnections
      })
      return yield* Effect.tryPromise({
        try: () => createPool(config.database),
        catch: (error) => new DatabaseError({ 
          cause: error, 
          operation: "create_pool" 
        })
      })
    }),
    (pool) =>
      Effect.gen(function* () {
        yield* logger.info("Closing database pool")
        yield* Effect.tryPromise(() => pool.close()).pipe(
          Effect.catchAll((error) =>
            logger.error("Failed to close pool", { error })
          )
        )
      })
  )

  const query = (sql: string) =>
    Effect.gen(function* () {
      const connection = yield* Effect.acquireRelease(
        Effect.tryPromise(() => pool.acquire()),
        (conn) => Effect.sync(() => pool.release(conn))
      )

      return yield* Effect.tryPromise({
        try: () => connection.query(sql),
        catch: (error) => new QueryError({ cause: error, sql })
      })
    })

  const transaction = <A, E>(
    work: Effect.Effect<A, E>
  ): Effect.Effect<A, E | DatabaseError> =>
    Effect.gen(function* () {
      const connection = yield* Effect.acquireRelease(
        Effect.tryPromise(() => pool.acquire()),
        (conn) => Effect.sync(() => pool.release(conn))
      )

      yield* Effect.tryPromise(() => connection.beginTransaction())

      const result = yield* work.pipe(
        Effect.catchAll((error) =>
          Effect.gen(function* () {
            yield* Effect.tryPromise(() => connection.rollback()).pipe(
              Effect.ignore
            )
            return yield* Effect.fail(error)
          })
        )
      )

      yield* Effect.tryPromise(() => connection.commit())
      return result
    })

  return { query, transaction } as const
})

// Layer automatically handles resource lifecycle
export const DatabaseServiceLive = Layer.scoped(
  DatabaseService,
  makeDatabaseService
)
```

**Key Points**:

- Use `Layer.scoped` for services with resources
- Resources are acquired when layer is provided
- Resources are released when scope ends
- Perfect for connection pools, file handles, etc.

```typescript
        )

        // Force close any remaining connections
        yield* Effect.tryPromise(() => pool.close()).pipe(
          Effect.catchAll((error) =>
            logger.error("Error closing pool", { error })
          )
        )

        yield* logger.info("Database connection pool closed")
      })
  )

  // Health check
  const healthCheck = Effect.gen(function* () {
    const connection = yield* Effect.acquireRelease(
      Effect.tryPromise(() => pool.acquire()),
      (conn) => Effect.sync(() => pool.release(conn))
    )

    yield* Effect.tryPromise({
      try: () => connection.query("SELECT 1"),
      catch: (error) => new DatabaseError({ 
        cause: error, 
        operation: "health_check" 
      })
    })
  })

  return {
    query: (sql: string) => withConnection(pool, (conn) =>
      Effect.tryPromise({
        try: () => conn.query(sql),
        catch: (error) => new QueryError({ cause: error, sql })
      })
    ),
```

### 7.5 Resource Safety Guarantees

#### Interruption Safety

Effect guarantees cleanup runs even when interrupted:

```typescript
// ✅ Interruption-safe resource management
const interruptibleOperation = Effect.gen(function* () {
  const resource = yield* Effect.acquireRelease(
    Effect.gen(function* () {
      yield* Effect.log("Acquiring resource")
      return yield* acquireResource()
    }),
    (resource) =>
      Effect.gen(function* () {
        yield* Effect.log("Releasing resource (even on interruption)")
        yield* releaseResource(resource)
      })
  )

  // Long-running operation that can be interrupted
  yield* longRunningWork(resource).pipe(
    Effect.ensuring(
      Effect.log("Cleanup always runs")
    )
  )
})

// Test interruption
const testInterruption = Effect.gen(function* () {
  const fiber = yield* Effect.fork(interruptibleOperation)
  
  // Interrupt after 1 second
  yield* Effect.sleep("1 second")
  yield* Fiber.interrupt(fiber)
  
  // Cleanup still ran!
})
```

**Guarantees**:

- Cleanup runs on success, failure, or interruption
- Cleanup cannot be interrupted (runs in uninterruptible region)
- Resources are never leaked

#### Uninterruptible Cleanup

For critical cleanup that must complete:

```typescript
// ✅ Uninterruptible cleanup regions
const criticalCleanup = Effect.gen(function* () {
  const resource = yield* acquireResource()

  yield* performWork(resource).pipe(
    Effect.ensuring(
      Effect.uninterruptible(
        Effect.gen(function* () {
          // This cleanup cannot be interrupted
          yield* criticalCleanupStep1(resource)
          yield* criticalCleanupStep2(resource)
          yield* criticalCleanupStep3(resource)
        })
      )
    )
  )
})
```

**When to use uninterruptible**:

- Critical database transactions that must complete
- State that must be consistent after cleanup
- Resources that cannot be partially released

```typescript
      )

      assert.strictEqual(result, "used resource")
      
      const wasCleanedUp = yield* Ref.get(cleaned)
      assert.isTrue(wasCleanedUp)
    })
  )

  it.effect("cleans up on failure", () =>
    Effect.gen(function* () {
      const cleaned = yield* Ref.make(false)

      const result = yield* Effect.acquireRelease(
        Effect.succeed("resource"),
        () => Ref.set(cleaned, true)
      ).pipe(
        Effect.flatMap(() => Effect.fail("error")),
        Effect.flip // Convert to success for testing
      )

      assert.strictEqual(result, "error")
      
      const wasCleanedUp = yield* Ref.get(cleaned)
      assert.isTrue(wasCleanedUp)
    })
  )

  it.effect("cleans up on interruption", () =>
    Effect.gen(function* () {
      const cleaned = yield* Ref.make(false)

      const operation = Effect.acquireRelease(
        Effect.succeed("resource"),
        () => Ref.set(cleaned, true)
      ).pipe(
        Effect.flatMap(() => Effect.never) // Never completes
      )

      const fiber = yield* Effect.fork(operation)
      yield* Fiber.interrupt(fiber)

      const wasCleanedUp = yield* Ref.get(cleaned)
      assert.isTrue(wasCleanedUp)
    })
  )

  it.effect("resource pool maintains size", () =>
    Effect.gen(function* () {
      const pool = yield* makeResourcePool({
        create: Effect.succeed({ id: Math.random() }),
        destroy: () => Effect.void,
        validate: () => Effect.succeed(true),
        size: 5
      })

      const initialSize = yield* pool.size
      assert.strictEqual(initialSize, 5)

      // Use resources concurrently
      yield* Effect.all(
        Array.from({ length: 20 }, () =>
          pool.withResource(() => Effect.sleep("10 millis"))
        ),
        { concurrency: "unbounded" }
      )

      const finalSize = yield* pool.size
      assert.strictEqual(finalSize, 5)
    })
  )
})
```

### 7.6 Best Practices

#### Resource Management Checklist

✅ **DO**:

- Always use `Effect.acquireRelease` or `Scope` for resources
- Handle errors in release functions - never let them fail
- Add timeouts to cleanup operations
- Log all cleanup failures for debugging
- Test resource cleanup under all conditions (success, failure, interruption)
- Use `Layer.scoped` for services managing resources
- Implement health checks for pooled resources
- Validate resources before reuse in pools

❌ **DON'T**:

- Never manually manage resources with try-finally
- Don't let release functions throw or fail
- Don't forget to handle interruption
- Don't leak resources on early returns
- Don't create unbounded resource pools
- Don't ignore cleanup errors silently
- Don't mix manual and Effect resource management

#### Resource Management Patterns Summary

|Pattern|Use Case|Key Benefit|
|---|---|---|
|`acquireRelease`|Single resource with cleanup|Guaranteed cleanup|
|`Scope`|Multiple related resources|Automatic lifecycle|
|`ensuring`|Guaranteed side-effect cleanup|Finally-block equivalent|
|Resource Pool|Expensive resources|Reuse and limiting|
|`Layer.scoped`|Service-level resources|Integrated lifecycle|
|Nested resources|Dependent resources|Ordered cleanup|
|Conditional resources|Optional features|Flexible acquisition|

#### Common Pitfalls

1. **Forgetting to catch errors in release**: Always wrap release logic in error handlers
2. **Not handling interruption**: Test that cleanup runs when operations are interrupted
3. **Blocking cleanup**: Add timeouts to prevent hanging on cleanup
4. **Resource leaks in pools**: Validate and replace invalid resources
5. **Not testing cleanup**: Write tests for all cleanup paths
6. **Mixing patterns**: Don't mix manual cleanup with Effect patterns

#### Resource Management Decision Tree

```
Does your operation need a resource?
├─ Single simple resource?
│  └─ Use Effect.acquireRelease
├─ Multiple related resources?
│  └─ Use Scope or nested acquireRelease
├─ Resource pool?
│  └─ Implement pool with Queue + Semaphore
├─ Service-level resource?
│  └─ Use Layer.scoped
└─ Just need guaranteed cleanup?
   └─ Use Effect.ensuring
```
