# 14. Development Workflow

## 14.1 Development Process

### Research → Plan → Implement Pattern

**Core Principle**: Never jump straight to coding. Follow a structured development process with reality checkpoints.

#### Phase 1: Research

Before writing any code, thoroughly understand the problem space:

```typescript
// ❌ BAD: Jumping straight to implementation
const processPayment = (amount: number) => {
  // Started coding without understanding requirements
  return Effect.succeed(amount * 1.1)
}

// ✅ GOOD: Research first
// 1. What payment methods are supported?
// 2. What validation is required?
// 3. What error cases exist?
// 4. What external services are involved?
// 5. What are the performance requirements?
```

**Research Checklist:**
- [ ] Review existing codebase patterns
- [ ] Identify related modules and dependencies
- [ ] Study test files for usage examples
- [ ] Understand error handling requirements
- [ ] Check for similar implementations
- [ ] Review relevant Effect modules documentation

#### Phase 2: Planning

Create a detailed implementation plan with validation checkpoints:

```typescript
/**
 * Implementation Plan: Payment Processing Service
 *
 * 1. Define Error Types
 *    - PaymentValidationError
 *    - PaymentProcessingError
 *    - PaymentGatewayError
 *    Checkpoint: Compile and lint error definitions
 *
 * 2. Define Schemas
 *    - PaymentRequest schema
 *    - PaymentResponse schema
 *    - PaymentMethod union type
 *    Checkpoint: Test schema validation
 *
 * 3. Implement Service Interface
 *    - Define PaymentService tag
 *    - Specify method signatures
 *    Checkpoint: Type-check interface
 *
 * 4. Implement Core Logic
 *    - Payment validation
 *    - Gateway integration
 *    - Transaction recording
 *    Checkpoint: Write and run tests
 *
 * 5. Add Observability
 *    - Logging
 *    - Tracing spans
 *    - Error reporting
 *    Checkpoint: Test with telemetry
 *
 * 6. Integration
 *    - Create service layer
 *    - Add to AppLayer
 *    - Integration tests
 *    Checkpoint: Full test suite passes
 */
```

**Planning Best Practices:**
- Identify all validation checkpoints
- Consider edge cases and error scenarios
- Plan for observability from the start
- Design for testability
- Document assumptions and constraints

#### Phase 3: Implementation

Execute with frequent validation and reality checkpoints:

```typescript
// Step 1: Define errors (validate immediately)
class PaymentValidationError extends Data.TaggedError("PaymentValidationError")<{
  field: string
  message: string
}> {}

// ✅ CHECKPOINT: Run linting
// $ pnpm lint --fix src/services/PaymentService.ts

// Step 2: Define schemas (validate immediately)
const PaymentRequest = Schema.Struct({
  amount: Schema.Number.pipe(Schema.positive()),
  currency: Schema.Literal("USD", "EUR", "GBP"),
  method: Schema.Union(
    Schema.Struct({ type: Schema.Literal("card"), cardToken: Schema.String }),
    Schema.Struct({ type: Schema.Literal("bank"), accountId: Schema.String })
  )
})

// ✅ CHECKPOINT: Test schema compilation
// $ pnpm tsc

// Step 3: Implement service
export class PaymentService extends Effect.Service<PaymentService>()(
  "app/PaymentService",
  {
    effect: makePaymentService,
    dependencies: [PaymentGateway.Default, Database.Default]
  }
) {}

// ✅ CHECKPOINT: Write tests immediately
// $ pnpm test src/services/PaymentService.test.ts
```

### 🚨 MANDATORY FUNCTION DEVELOPMENT WORKFLOW 🚨

**ALWAYS follow this EXACT sequence when creating ANY new function:**

1. **Create function** - Write the function implementation in TypeScript file
2. **Lint TypeScript file** - `pnpm lint --fix <typescript_file.ts>`
3. **Check compilation** - `pnpm tsc`
4. **Lint TypeScript file again** - `pnpm lint --fix <typescript_file.ts>`
5. **Ensure compilation** - `pnpm tsc` again to double-check
6. **Write test** - Create comprehensive test for the function
7. **Compile test & lint test file** - `pnpm tsc` then `pnpm lint --fix <test_file.ts>`

**CRITICAL NOTES:**
- **ONLY LINT TYPESCRIPT FILES** (.ts files) - Do NOT lint markdown, JSON, or other file types
- **NEVER SKIP ANY STEP** - This workflow is MANDATORY for every single function
- **NEVER CONTINUE** to the next step until the current step passes completely
- **NEVER CREATE MULTIPLE FUNCTIONS** without completing this full workflow for each one

**Example Workflow:**

```bash
# 1. Create function in PaymentService.ts
# (Edit file with new processPayment function)

# 2. Lint immediately
pnpm lint --fix src/services/PaymentService.ts

# 3. Type check
pnpm tsc

# 4. Lint again
pnpm lint --fix src/services/PaymentService.ts

# 5. Type check again
pnpm tsc

# 6. Write test in PaymentService.test.ts
# (Create test file with comprehensive tests)

# 7. Type check and lint test
pnpm tsc
pnpm lint --fix src/services/PaymentService.test.ts
```

**After EVERY TypeScript file edit:**

```bash
# 🚨 CRITICAL: Always lint TypeScript files immediately after editing

```

**Before ANY commit:**

```bash
# Complete validation suite

```

**MANDATORY docgen Rule:**
- **ABSOLUTELY NEVER COMMIT if docgen fails**
- Fix ALL compilation errors in JSDoc examples

- Examples must use correct imports and API usage

### When Stuck

If you find yourself spiraling into complex solutions:

1. **Stop and Analyze**: Don't continue digging deeper
2. **Break Down**: Divide the problem into smaller, manageable parts
3. **Use Parallel Approaches**: Consider multiple solutions simultaneously
4. **Research First**: Look for existing patterns before creating new ones
5. **Simplify**: Choose the simplest solution that meets requirements
6. **Ask for Guidance**: Request help rather than guessing
7. **Reality Check**: Validate your approach against requirements

```typescript
// ❌ ANTI-PATTERN: Spiraling into complexity
const processData = (input: ComplexType) =>
  Effect.gen(function* () {
    // Started simple but kept adding complexity
    const step1 = yield* transform1(input)
    const step2 = yield* transform2(step1)
    const step3 = yield* transform3(step2)
    // ... 15 more transformations later
    const step18 = yield* transform18(step17)
    // Now completely lost, not sure what the goal was
  })

// ✅ CORRECT: Break down and restart with clear plan
const processData = (input: ComplexType) =>
  Effect.gen(function* () {
    // Clear phases with validation
    const validated = yield* validateInput(input)
    const transformed = yield* applyBusinessRules(validated)
    const result = yield* formatOutput(transformed)
    return result
  })
```

### Test Quality Standards

**Clear Test Structure:**

```typescript
it.effect("should process payment successfully", () =>
  Effect.gen(function* () {
    // Arrange: Set up test data and dependencies
    const mockGateway = createMockPaymentGateway("success")
    const request = createValidPaymentRequest()
    
    // Act: Execute the operation
    const result = yield* PaymentService.processPayment(request).pipe(
      Effect.provide(MockPaymentLayer(mockGateway))
    )
    
    // Assert: Verify results
    assert.strictEqual(result.status, "completed")
    assert.strictEqual(result.transactionId, "mock-txn-123")
  }))
```

**Testing Error Scenarios:**

```typescript
it.effect("should handle gateway timeout", () =>
  Effect.gen(function* () {
    const mockGateway = createMockPaymentGateway("timeout")
    
    // Use Effect.flip to test error cases
    const error = yield* PaymentService.processPayment(request).pipe(
      Effect.provide(MockPaymentLayer(mockGateway)),
      Effect.flip
    )
    
    assert.strictEqual(error._tag, "PaymentGatewayError")
    assert.isTrue(error.message.includes("timeout"))
  }))
```

**Testing with TestClock (MANDATORY for time-dependent code):**

```typescript
import { TestClock } from "effect/TestClock"

it.effect("should retry with exponential backoff", () =>
  Effect.gen(function* () {
    const fiber = yield* Effect.fork(
      retryableOperation.pipe(
        Effect.retry({
          times: 3,
          schedule: Schedule.exponential("1 second")
        })
      )
    )
    
    // Fast-forward time instead of waiting
    yield* TestClock.adjust("1 second")
    yield* TestClock.adjust("2 seconds")
    yield* TestClock.adjust("4 seconds")
    
    const result = yield* Fiber.join(fiber)
    assert.strictEqual(result, expectedValue)
  }))
```

### Test Independence

**Each test must be independent:**

```typescript
// ❌ BAD: Tests depend on execution order
let sharedState: User | null = null

it.effect("creates user", () => 
  Effect.gen(function* () {
    sharedState = yield* createUser(data)
    assert.isNotNull(sharedState)
  }))

it.effect("updates user", () => // Depends on previous test!
  Effect.gen(function* () {
    const updated = yield* updateUser(sharedState!.id, updates)
    assert.strictEqual(updated.name, "Updated")
  }))

// ✅ GOOD: Tests are independent
it.effect("creates user", () =>
  Effect.gen(function* () {
    const user = yield* createUser(data)
    assert.isNotNull(user)
    assert.strictEqual(user.name, data.name)
  }))

it.effect("updates user", () =>
  Effect.gen(function* () {
    // Each test creates its own setup
    const user = yield* createUser(data)
    const updated = yield* updateUser(user.id, updates)
    assert.strictEqual(updated.name, "Updated")
  }))
```

## 14.4 Refactoring Guidelines

### Pipe Refactoring Standards

**Rule 1: Pipe Value-First to Function-First**

Convert old-style `pipe(value, fn1, fn2)` to modern `pipe(fn1(value), fn2)`:

```typescript
// BEFORE (value-first):
const result = pipe(
  numbers,
  Array.filter(n => n % 2 === 0),
  Array.map(n => n * n),
  Array.take(3)
)

// AFTER (function-first):
const result = pipe(
  Array.filter(numbers, n => n % 2 === 0),
  Array.map(n => n * n),
  Array.take(3)
)
```

**Rule 2: Import Alias Standardization**

Update single-letter module aliases to descriptive names:

```typescript
// BEFORE:
import { Array as A, Function as F } from "effect"

const result = pipe(
  items,
  A.filter(predicate),
  A.map(transform)
)

// AFTER:
import { Array as Arr, Function as Fn } from "effect"

const result = pipe(
  Arr.filter(items, predicate),
  Arr.map(transform)
)
```

**Standard Aliases:**
- `Array as A` → `Array as Arr`
- `Function as F` → `Function as Fn`
- `Option as O` → Keep as `Option as O`
- `Schema as S` → Keep as `Schema as S`
- `Effect` → No alias (use directly)

**Rule 3: Update All References**

When changing import aliases, update ALL usage throughout the file:

```typescript
// BEFORE:
import { Array as A } from "effect"

const filtered = A.filter(items, predicate)
const mapped = A.map(filtered, transform)
const result = pipe(items, A.filter(predicate), A.map(transform))

// AFTER:
import { Array as Arr } from "effect"

const filtered = Arr.filter(items, predicate)
const mapped = Arr.map(filtered, transform)
const result = pipe(Arr.filter(items, predicate), Arr.map(transform))
```

**Rule 4: Maintain Functionality**

Refactoring must preserve:
- Exact same behavior and outputs
- All TypeScript types and type safety
- All comments and explanations
- Code block syntax highlighting
- Test coverage and passing tests

### Service Refactoring

**Migrating from Old to New Service Pattern:**

```typescript
// OLD PATTERN:
export interface UserService {
  readonly getUser: (id: string) => Effect.Effect<User, UserError>
}

export const UserService = Context.GenericTag<UserService>("UserService")

const makeUserService = Effect.gen(function* () {
  const db = yield* Database
  return {
    getUser: (id) => db.users.findById(id)
  }
})

export const UserServiceLive = Layer.effect(UserService, makeUserService)

// NEW PATTERN:
export class UserService extends Effect.Service<UserService>()(
  "app/UserService",
  {
    effect: Effect.gen(function* () {
      const db = yield* Database
      return {
        getUser: (id: string) => db.users.findById(id)
      } as const
    }),
    dependencies: [Database.Default]
  }
) {}

// Usage automatically gets UserService.Default layer
```

**Refactoring Checklist:**
- [ ] Replace `Context.GenericTag` with `Effect.Service`
- [ ] Add `dependencies` array if service has dependencies
- [ ] Use `effect` or `scoped` for service initialization
- [ ] Add `as const` to return value for type inference
- [ ] Update all imports to use `ServiceName.Default`
- [ ] Update tests to use new service pattern
- [ ] Remove old `Layer.effect` definitions

### Schema Refactoring

**Migrating from Struct to Class:**

```typescript
// OLD: Basic Struct
const User = Schema.Struct({
  id: Schema.String,
  name: Schema.String,
  email: Schema.String
})

type User = Schema.Schema.Type<typeof User>

// NEW: Schema.Class with methods
class User extends Schema.Class<User>("User")({
  id: Schema.String,
  name: Schema.String,
  email: Schema.String
}) {
  get displayName() {
    return `${this.name} (${this.email})`
  }
}

// Updates validation calls
const validated = yield* Schema.decodeUnknown(User)(input)
// No change needed - Schema.Class works the same way
```

**Refactoring Checklist:**
- [ ] Convert `Schema.Struct` to `Schema.Class`
- [ ] Add methods if beneficial
- [ ] Update type extraction (remove separate `type` definition)
- [ ] Ensure validation calls still work
- [ ] Add tests for new methods
- [ ] Update documentation

### Effect.gen vs .pipe Refactoring

**When to Refactor to Effect.gen:**

```typescript
// BEFORE: Complex pipe chain
const processOrder = (order: Order) => 
  Effect.succeed(order).pipe(
    Effect.flatMap(validateOrder),
    Effect.flatMap(calculateTotals),
    Effect.flatMap(applyDiscounts),
    Effect.flatMap(processPayment),
    Effect.flatMap(updateInventory),
    Effect.tap(sendConfirmation)
  )

// AFTER: Clear Effect.gen
const processOrder = (order: Order) =>
  Effect.gen(function* () {
    const validated = yield* validateOrder(order)
    const totaled = yield* calculateTotals(validated)
    const discounted = yield* applyDiscounts(totaled)
    const paid = yield* processPayment(discounted)
    const updated = yield* updateInventory(paid)
    yield* sendConfirmation(updated)
    return updated
  })
```

**When to Refactor to .pipe:**

```typescript
// BEFORE: Simple Effect.gen
const getUserName = (id: string) =>
  Effect.gen(function* () {
    const user = yield* getUser(id)
    return user.name
  })

// AFTER: Simple .pipe
const getUserName = (id: string) =>
  getUser(id).pipe(
    Effect.map(user => user.name)
  )
```
