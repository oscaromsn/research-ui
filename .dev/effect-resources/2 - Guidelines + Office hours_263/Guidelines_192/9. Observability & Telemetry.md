## 9. Observability & Telemetry

### Core Principle

Observability is essential for understanding system behavior in production. Effect-TS provides built-in tracing, structured logging, and span management that integrate seamlessly with distributed tracing systems like OpenTelemetry.

## 9.1 Logging

### Log Levels

Effect provides six log levels for different severity scenarios:

```typescript
import { Effect } from "effect"

const comprehensiveLogging = Effect.gen(function* () {
  // Fatal: Service stopped, manual recovery required
  yield* Effect.logFatal("Database connection lost permanently")

  // Error: Service stopped, automatic recovery possible
  yield* Effect.logError("Failed to process payment, will retry")

  // Warning: Normal processing, inexplicable event occurred
  yield* Effect.logWarning("API rate limit approaching threshold")

  // Info: Normal processing progress record (default)
  yield* Effect.log("User authentication successful")

  // Debug: Development-time output
  yield* Effect.logDebug("Request payload", { body: requestData })

  // Trace: Very detailed diagnostic information
  yield* Effect.logTrace("Entering function processUser")
})
```

**Log Level Guidelines:**
- **Fatal**: System cannot continue, requires manual intervention
- **Error**: Operation failed, may retry automatically
- **Warning**: Unusual but handled condition
- **Info**: Normal operation milestones
- **Debug**: Diagnostic information for development
- **Trace**: Very detailed execution flow for debugging

### Structured Logging

**CRITICAL**: Always use objects for log data, never string concatenation.

```typescript
// ❌ BAD: String concatenation
yield* Effect.log("User " + user.id + " logged in at " + timestamp)

// ✅ GOOD: Structured objects
yield* Effect.log("User logged in", {
  userId: user.id,
  timestamp,
  ip: request.ip,
  userAgent: request.headers.userAgent
})
```

**Benefits of Structured Logging:**
- Machine-readable log data
- Easy filtering and searching
- Consistent log format
- Better integration with log aggregation tools


```typescript
      // Log the error
      yield* Effect.logError("Operation failed", {
        error: error._tag,
```


## 9.2 Tracing & Spans

### Effect.withSpan (Creating Spans)

Add distributed tracing spans to track operations:

```typescript
// Basic span
const fetchUser = (id: string) =>
  Effect.gen(function* () {
    const user = yield* database.query("SELECT * FROM users WHERE id = ?", id)
    return user
  }).pipe(
    Effect.withSpan("user.fetch", {
      attributes: {
        "user.id": id,
        "operation": "database.query"
      }
    })
  )

// Nested spans
const getUserWithProfile = (id: string) =>
  Effect.gen(function* () {
    const user = yield* fetchUser(id).pipe(
      Effect.withSpan("user.fetch")
    )

    const profile = yield* fetchProfile(user.profileId).pipe(
      Effect.withSpan("profile.fetch")
    )

    return { user, profile }
  }).pipe(
    Effect.withSpan("user.get_with_profile", {
      attributes: {
        "user.id": id,
        "operation.type": "composite"
      }
    })
  )
```

**Span Naming Conventions:**
- Use dot notation: `service.operation`
- Examples: `user.create`, `payment.process`, `cache.invalidate`
- Be consistent across your application
- Use lowercase with underscores for multi-word operations

## 9.3 Custom Logger Implementation

### Logger.make (Custom Loggers)

Create custom logger implementations for specific output formats:

```typescript
import { Logger, Effect, Layer } from "effect"

// Custom JSON logger
const makeJsonLogger = Effect.sync(() => {
  return Logger.make((options) => {
    const { logLevel, message, annotations, spans, fiberId } = options

    const logEntry = {
      timestamp: new Date().toISOString(),
      level: logLevel.label,
      message,
      annotations: Object.fromEntries(annotations),
      spanId: spans.length > 0 ? spans[0].spanId : undefined,
      traceId: spans.length > 0 ? spans[0].traceId : undefined,
      fiberId: fiberId.id
    }

    console.log(JSON.stringify(logEntry))
  })
})

export const JsonLoggerLive = Layer.succeed(Logger.Logger, makeJsonLogger)
```

### ConsoleLogger (Development Logging)

Simple console logger for development:

```typescript
// Development logger with formatted output
const makeConsoleLogger = Effect.sync(() => {
  return Logger.make((options) => {
    const { logLevel, message, annotations } = options

    const color = {
      Fatal: '\x1b[41m',    // Red background
      Error: '\x1b[31m',    // Red
```

**Logger with Log Aggregation:**

```typescript
// Logger that sends logs to aggregation service
const makeAggregationLogger = Effect.gen(function* () {
  const httpClient = yield* HttpClient
  const config = yield* ConfigService

  const buffer: LogEntry[] = []
  const flushInterval = 5000 // 5 seconds

  // Flush buffer periodically
  const flushLogs = Effect.gen(function* () {
    if (buffer.length === 0) return

    const logs = [...buffer]
    buffer.length = 0

    yield* httpClient.post(`${config.getLogEndpoint()}/bulk`, {
      body: { logs }
    }).pipe(
      Effect.catchAll((error) =>
        Effect.log("Failed to send logs", { error })
      )
    )
  })

  // Start periodic flush
  yield* Effect.forkDaemon(
    Effect.repeat(flushLogs, Schedule.spaced(flushInterval))
  )

  return Logger.make((options) => {
    buffer.push({
      timestamp: Date.now(),
      level: options.logLevel.label,
      message: options.message,
      annotations: Object.fromEntries(options.annotations)
    })
  })
})

export const AggregationLoggerLive = Layer.scoped(
  Logger.Logger,
  makeAggregationLogger
)
```

```typescript
// Performance tracking utility
const trackPerformance = <A, E, R>(
  operation: Effect.Effect<A, E, R>,
  operationName: string,
  thresholdMs: number

  Effect.gen(function* () {
```

**Latency Tracking:**

```typescript
// Track latency percentiles
class LatencyTracker {
  private measurements: number[] = []

  track(duration: number): void {
    this.measurements.push(duration)
    if (this.measurements.length > 1000) {
      this.measurements.shift()
    }
  }

  getPercentile(p: number): number {
    const sorted = [...this.measurements].sort((a, b) => a - b)
    const index = Math.ceil((p / 100) * sorted.length) - 1
    return sorted[index]
  }

  getStats() {
    return {
      p50: this.getPercentile(50),
      p90: this.getPercentile(90),
      p95: this.getPercentile(95),
      p99: this.getPercentile(99)
    }
  }
}

// Use with Effect
const withLatencyTracking = <A, E, R>(
  operation: Effect.Effect<A, E, R>,
  tracker: LatencyTracker,
  operationName: string
) =>
  Effect.gen(function* () {
    const startTime = Date.now()
    const result = yield* operation
    const duration = Date.now() - startTime

    tracker.track(duration)

    yield* Effect.log("Operation latency", {
      operation: operationName,
      duration_ms: duration,
      ...tracker.getStats()
    })

    return result
  })
```

### Error Tracking

Monitor error rates and patterns:

```typescript
// Error rate tracking
class ErrorRateTracker {
  private errors: Map<string, number> = new Map()
  private total: number = 0

  recordError(errorTag: string): void {
    this.total++
    const current = this.errors.get(errorTag) || 0
    this.errors.set(errorTag, current + 1)
  }

  getErrorRate(errorTag: string): number {
    const count = this.errors.get(errorTag) || 0
    return this.total > 0 ? count / this.total : 0
  }

  getAllRates(): Record<string, number> {
    const rates: Record<string, number> = {}
    for (const [tag, count] of this.errors.entries()) {
      rates[tag] = count / this.total
    }
    return rates
  }
}

// Track errors in operations
const withErrorTracking = <A, E extends { _tag: string }, R>(
  operation: Effect.Effect<A, E, R>,
  tracker: ErrorRateTracker
) =>
  operation.pipe(
    Effect.tapError((error) =>
      Effect.sync(() => {
        tracker.recordError(error._tag)

        Effect.logError("Error occurred", {
          errorType: error._tag,
          errorRate: tracker.getErrorRate(error._tag),
          allRates: tracker.getAllRates()
        })
      })
    )
  )
```

```typescript
// Alert based on error thresholds
```

```typescript
      "pool.idle": stats.idle,
      "pool.utilization": stats.active / stats.total
    })

    // Alert on high utilization
    if (stats.active / stats.total > 0.9) {
      yield* Effect.logWarning("Connection pool near capacity", {
        utilization: stats.active / stats.total
      })
    }
  })

// Monitor fiber counts
const monitorFiberCount = Effect.gen(function* () {
  const fiberCount = yield* Effect.descriptor.pipe(
    Effect.map(descriptor => descriptor.id)
  )

  yield* Effect.log("Active fiber count", { fiberCount })

  yield* Effect.annotateCurrentSpan({
    "fibers.count": fiberCount
  })
})

// Monitor queue depths
const monitorQueue = <A>(queue: Queue.Queue<A>) =>
  Effect.gen(function* () {
    const size = yield* Queue.size(queue)
    const capacity = queue.capacity

    yield* Effect.log("Queue stats", {
      size,
      capacity,
      utilization: capacity === Number.POSITIVE_INFINITY ? 0 : size / capacity
    })

    if (capacity !== Number.POSITIVE_INFINITY && size / capacity > 0.8) {
      yield* Effect.logWarning("Queue near capacity", {
        size,
        capacity
      })
    }
  })
```

**Periodic Resource Monitoring:**

```typescript
// Monitor resources on schedule
const startResourceMonitoring = Effect.gen(function* () {
  const pool = yield* DatabaseConnectionPool
  const queue = yield* WorkQueue

  yield* Effect.repeat(
    Effect.gen(function* () {
      yield* monitorConnectionPool(pool)
      yield* monitorQueue(queue)
```

## Best Practices Summary

### Logging
1. **Structured Data**: Always use objects, never string concatenation
2. **Appropriate Levels**: Use correct log levels for severity
3. **Context Annotations**: Add persistent context with `annotateLogs`
4. **Error Details**: Log full error context including causes
5. **Performance**: Consider log volume in production

### Tracing
1. **Use Effect.fn**: Get automatic spans with better debugging
2. **Descriptive Spans**: Use clear, consistent span names
3. **Rich Attributes**: Add relevant attributes to spans
4. **Nested Spans**: Create span hierarchies for complex operations
5. **Correlation IDs**: Include trace/request IDs for distributed tracing

### Custom Loggers
1. **Environment-Specific**: Different loggers for dev/prod
2. **Structured Output**: JSON for machine processing
3. **Filtering**: Filter by log level appropriately
4. **Performance**: Consider buffering for high-volume logging
5. **Integration**: Integrate with log aggregation services

### Telemetry
1. **OpenTelemetry**: Use standard OTLP exporters
2. **Resource Attributes**: Include service name, version, instance ID
3. **Instrumentation**: Auto-instrument HTTP, database operations
4. **Consistent Context**: Propagate trace context across boundaries
5. **Sampling**: Configure appropriate sampling rates for production

### Monitoring
1. **Track Performance**: Monitor operation latency and throughput
2. **Error Rates**: Track error frequencies and patterns
3. **Resource Usage**: Monitor pools, queues, memory, fibers
4. **Alert Thresholds**: Set meaningful thresholds for alerts
5. **Periodic Checks**: Schedule regular health checks

By following these observability patterns, you create systems that are easy to debug, monitor, and optimize in production environments.
