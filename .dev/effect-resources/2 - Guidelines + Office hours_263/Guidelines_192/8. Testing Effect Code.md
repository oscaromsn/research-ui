## 8. Testing Effect Code

### 8.1 Testing Framework Selection

**CRITICAL RULE**: Testing framework selection is MANDATORY based on the code being tested.

#### When to Use @effect/vitest

**MANDATORY** for modules that work with Effect values:

- Functions returning `Effect<A, E, R>` types
- Effect modules: Effect, Stream, Layer, TestClock, Ref, Queue, Semaphore, etc.
- Services using Context.Tag and Layer
- Any code involving Effect composition or generators

```typescript
import { assert, describe, it } from "@effect/vitest"
import * as Effect from "effect/Effect"

describe("Effect-based code", () => {
  it.effect("should use @effect/vitest", () =>
    Effect.gen(function* () {
      const result = yield* someEffectOperation()
      assert.strictEqual(result, expected)
    })
  )
})
```

#### When to Use Regular vitest

**MANDATORY** for pure TypeScript functions:

- Pure functions without Effect types
- Utility modules: Graph, Data, Equal, Chunk, Array, String, Number
- Simple data transformations
- Synchronous operations without Effect

```typescript
import { describe, expect, it } from "vitest"

describe("Pure functions", () => {
  it("should use regular vitest", () => {
    const result = pureSyncFunction(input)
    expect(result).toBe(expected)
  })
})
```

#### Decision Matrix

| Code Characteristic | Framework | Import Pattern |
|-------------------|-----------|----------------|
| Returns `Effect<A, E, R>` | @effect/vitest | `import { assert, describe, it } from "@effect/vitest"` |
| Uses `yield*` syntax | @effect/vitest | Use `it.effect()` |
| Accesses services via Context | @effect/vitest | Provide mock layers |
| Pure TypeScript function | vitest | `import { describe, expect, it } from "vitest"` |
| Synchronous without Effect | vitest | Use regular `it()` |

### 8.2 Test Structure

#### The it.effect Pattern (MANDATORY for Effect Code)

**CRITICAL**: Always use `it.effect` for Effect-based tests. Never use `Effect.runSync` with regular `it`.

**FORBIDDEN**: Using `expect` from vitest in Effect tests.

**MANDATORY**: Import `{ assert, describe, it }` from `@effect/vitest`.

```typescript
import { assert, describe, it } from "@effect/vitest"
import * as Effect from "effect/Effect"
import * as SomeModule from "effect/SomeModule"

describe("ModuleName", () => {
  describe("feature group", () => {
    // ✅ CORRECT: Using it.effect with Effect.gen
    it.effect("should perform operation successfully", () =>
      Effect.gen(function* () {
        const result = yield* SomeModule.operation()
        
        // Use assert methods, NOT expect
        assert.strictEqual(result, expectedValue)
        assert.deepStrictEqual(complexResult, expectedObject)
        assert.isTrue(booleanResult)
        assert.isFalse(negativeResult)
      })
    )

    // ✅ CORRECT: Testing with dependencies
    it.effect("should handle errors correctly", () =>
      Effect.gen(function* () {
        const service = yield* MyService
        const result = yield* service.operation()
        assert.strictEqual(result.status, "success")
      }).pipe(Effect.provide(MyService.Default))
    )
  })
})
```

#### Wrong Patterns (NEVER USE)

```typescript
// ❌ WRONG: Using Effect.runSync with regular it
import { describe, expect, it } from "vitest"

it("test", () => {
  const result = Effect.runSync(
    Effect.gen(function* () {
      return yield* someEffect
    })
  )
  expect(result).toBe(value) // Wrong assertion method
})

// ❌ WRONG: Using expect instead of assert in Effect tests
it.effect("test", () =>
  Effect.gen(function* () {
    const result = yield* someEffect
    expect(result).toBe(value) // Should use assert.strictEqual
  })
)
```

```typescript
// Boolean assertions

assert.isFalse(condition)

// Null/Undefined assertions
```

Use `it.scoped` for tests requiring resource management:


### 8.3 Testing Patterns

#### Success Case Testing


#### Error Testing with Effect.flip

**CRITICAL**: Use `Effect.flip` to put errors in the success channel for testing:

```typescript
describe("Error handling", () => {
  it.effect("should fail when user not found", () =>
    Effect.gen(function* () {
      const service = yield* UserService
      const errorEffect = service.getUser("nonexistent")
      
      // Use Effect.flip to capture the error
      const error = yield* errorEffect.pipe(Effect.flip)
      
      assert.strictEqual(error._tag, "UserNotFoundError")
      assert.strictEqual(error.userId, "nonexistent")
    }).pipe(Effect.provide(TestLayer))
  )

  it.effect("should handle validation errors", () =>
    Effect.gen(function* () {
      const service = yield* UserService
      const invalidInput = {
        name: "",
        email: "invalid-email",
        age: -1
      }
      
      const error = yield* service.createUser(invalidInput).pipe(
        Effect.flip
      )
      
      assert.strictEqual(error._tag, "ValidationError")
      assert.isTrue(error.errors.length > 0)
    }).pipe(Effect.provide(TestLayer))
  )
})
```

#### Shadow Service Pattern (State Capture)

For verifying interactions with services:

```typescript
// Create shadow service with call tracking
const createShadowUserService = Effect.gen(function* () {
  const calls = yield* Ref.make<Array<{ method: string; args: unknown[] }>>([])
  
  const recordCall = (method: string, args: unknown[]) =>
    Ref.update(calls, (arr) => [...arr, { method, args }])
  
  return {
    service: {
      getUser: (id: string) =>
        Effect.gen(function* () {
          yield* recordCall("getUser", [id])
          return { id, name: "Test User", email: "test@example.com" }
        }),
      createUser: (data: CreateUserInput) =>
        Effect.gen(function* () {
          yield* recordCall("createUser", [data])
          return { id: "new-id", ...data }
        })
    },
    getCalls: Ref.get(calls),
    assertCalled: (method: string, times: number) =>
      Ref.get(calls).pipe(
        Effect.flatMap((calls) => {
          const count = calls.filter(c => c.method === method).length
          return count === times
            ? Effect.void
            : Effect.die(
                `Expected ${method} to be called ${times} times, but was called ${count} times`
              )
        })
      )
  }
})

// Use in tests
it.effect("should call createUser with correct data", () =>
  Effect.gen(function* () {
    const { service, getCalls } = yield* createShadowUserService
    
    yield* service.createUser({
      name: "John",
      email: "john@example.com",
      age: 30
    })
    
    const calls = yield* getCalls
    assert.strictEqual(calls.length, 1)
    assert.strictEqual(calls[0].method, "createUser")
  })
)
```

### 8.4 Time-Dependent Testing

**CRITICAL**: When testing time-dependent code, ALWAYS use `TestClock` to avoid flaky tests.

#### TestClock Usage (MANDATORY)

**NEVER** rely on real wall-clock time in tests. Always use `TestClock.advance()` to control time progression.

```typescript
import * as TestClock from "effect/TestClock"
import * as Fiber from "effect/Fiber"

describe("Time-dependent operations", () => {
  it.effect("should handle delays correctly", () =>
    Effect.gen(function* () {
      const fiber = yield* Effect.fork(
        Effect.sleep("5 seconds").pipe(
          Effect.as("completed")
        )
      )
      
      // Fast-forward time instead of waiting
      yield* TestClock.advance("5 seconds")
      
      const result = yield* Fiber.join(fiber)
      assert.strictEqual(result, "completed")
    })
  )

  it.scoped("should timeout correctly", () =>
    Effect.gen(function* () {
      const fiber = yield* Effect.fork(
        longRunningOperation().pipe(
          Effect.timeout("1 second")
        )
      )
      
      yield* TestClock.advance("1 second")
      
      const result = yield* Fiber.join(fiber)
      assert.isTrue(Option.isNone(result)) // Timeout returns None
    })
  )
})
```

#### Testing Scheduled Operations

```typescript
import * as Schedule from "effect/Schedule"

it.effect("should retry with exponential backoff", () =>
  Effect.gen(function* () {
    let attempts = 0
    
    const operation = Effect.gen(function* () {
      attempts++
      if (attempts < 3) {
        return yield* Effect.fail(new Error("Retry"))
      }
      return "success"
    })
    
    const fiber = yield* Effect.fork(
      operation.pipe(
        Effect.retry(
          Schedule.exponential("1 second").pipe(
            Schedule.compose(Schedule.recurs(5))
          )
        )
      )
    )
    
    // Advance time through retries
    yield* TestClock.advance("1 second")  // First retry
    yield* TestClock.advance("2 seconds") // Second retry
    
    const result = yield* Fiber.join(fiber)
    assert.strictEqual(result, "success")
    assert.strictEqual(attempts, 3)
  })
)
```

#### Testing Queue Operations with Time

```typescript
import * as Queue from "effect/Queue"

it.effect("should process queue items with delays", () =>
  Effect.gen(function* () {
    const queue = yield* Queue.bounded<string>(10)
    const processed: string[] = []
    
    // Producer
    const producer = Effect.gen(function* () {
      yield* Queue.offer(queue, "item1")
      yield* Effect.sleep("1 second")
      yield* Queue.offer(queue, "item2")
      yield* Effect.sleep("1 second")
      yield* Queue.offer(queue, "item3")
      yield* Queue.shutdown(queue)
    })
    
    // Consumer
    const consumer = Effect.gen(function* () {
      while (true) {
        const item = yield* Queue.take(queue)
        processed.push(item)
      }
    }).pipe(
      Effect.catchTag("QueueShutdown", () => Effect.void)
    )
    
    // Run concurrently
    const fiber1 = yield* Effect.fork(producer)
    const fiber2 = yield* Effect.fork(consumer)
    
    // Advance time to process all items
    yield* TestClock.advance("3 seconds")
    
    yield* Fiber.join(fiber1)
    yield* Fiber.join(fiber2)
    
    assert.deepStrictEqual(processed, ["item1", "item2", "item3"])
  })
)
```

#### Operations Requiring TestClock

Use TestClock for testing these Effect operations:

- `Effect.sleep()` and `Effect.delay()`
- `Effect.timeout()` and `Effect.timeoutFail()`
- `Effect.race()` with time-based effects
- `Schedule`-based operations (retry, repeat)
- Queue operations with time-based completion
- Any concurrent operations depending on timing
- Cached effects with TTL
- Semaphore operations with timeouts

### 8.5 Concurrency Testing

#### Testing Parallel Operations

```typescript
describe("Concurrent operations", () => {
  it.effect("should execute operations in parallel", () =>
    Effect.gen(function* () {
      const start = Date.now()
      
      const results = yield* Effect.all([
        Effect.sleep("1 second").pipe(Effect.as(1)),
        Effect.sleep("1 second").pipe(Effect.as(2)),
        Effect.sleep("1 second").pipe(Effect.as(3))
      ], { concurrency: "unbounded" })
      
      const duration = Date.now() - start
      
      assert.deepStrictEqual(results, [1, 2, 3])
      // All operations ran in parallel, should complete in ~1 second
      assert.isTrue(duration < 2000)
    })
  )

  it.effect("should respect concurrency limits", () =>
    Effect.gen(function* () {
      let concurrent = 0
      let maxConcurrent = 0
      
      const operation = Effect.gen(function* () {
        concurrent++
        maxConcurrent = Math.max(maxConcurrent, concurrent)
        yield* Effect.sleep("100 millis")
        concurrent--
      })
      
      yield* Effect.all(
        Array.from({ length: 10 }, () => operation),
        { concurrency: 3 }
      )
      
      assert.strictEqual(maxConcurrent, 3)
    })
  )
})
```

#### Testing Synchronization Primitives

```typescript
import * as Semaphore from "effect/Semaphore"
import * as Queue from "effect/Queue"
import * as Deferred from "effect/Deferred"

describe("Synchronization primitives", () => {
  it.effect("should test Semaphore mutual exclusion", () =>
    Effect.gen(function* () {
      const semaphore = yield* Semaphore.make(1)
      let concurrent = 0
      let maxConcurrent = 0
      
      const operation = semaphore.withPermits(1)(
        Effect.gen(function* () {
          concurrent++
          maxConcurrent = Math.max(maxConcurrent, concurrent)
          yield* Effect.sleep("10 millis")
          concurrent--
        })
      )
      
      yield* Effect.all(
        Array.from({ length: 10 }, () => operation),
        { concurrency: "unbounded" }
      )
      
      assert.strictEqual(maxConcurrent, 1)
    })
  )

  it.effect("should test Queue producer-consumer", () =>
    Effect.gen(function* () {
      const queue = yield* Queue.bounded<number>(5)
      const results: number[] = []
      
      const producer = Effect.gen(function* () {
        for (let i = 0; i < 10; i++) {
          yield* Queue.offer(queue, i)
        }
        yield* Queue.shutdown(queue)
      })
      
      const consumer = Effect.gen(function* () {
        while (true) {
          const item = yield* Queue.take(queue)
          results.push(item)
        }
      }).pipe(
        Effect.catchTag("QueueShutdown", () => Effect.void)
      )
      
      yield* Effect.all([
        Effect.fork(producer),
        Effect.fork(consumer)
      ], { concurrency: "unbounded" }).pipe(
        Effect.flatMap((fibers) => 
          Effect.all(fibers.map(Fiber.join))
        )
      )
      
      assert.strictEqual(results.length, 10)
      assert.deepStrictEqual(results, Array.from({ length: 10 }, (_, i) => i))
    })
  )

  it.effect("should test Deferred coordination", () =>
    Effect.gen(function* () {
      const deferred = yield* Deferred.make<string>()
      let value: string | null = null
      
      const waiter = Effect.gen(function* () {
        value = yield* Deferred.await(deferred)
      })
      
      const provider = Effect.gen(function* () {
        yield* Effect.sleep("100 millis")
        yield* Deferred.succeed(deferred, "hello")
      })
      
      yield* Effect.all([
        Effect.fork(waiter),
        Effect.fork(provider)
      ], { concurrency: "unbounded" }).pipe(
        Effect.flatMap((fibers) => 
          Effect.all(fibers.map(Fiber.join))
        )
      )
      
      assert.strictEqual(value, "hello")
    })
  )
})
```

### 8.8 Testing Best Practices

#### Test All Paths

```typescript
describe("Comprehensive testing", () => {
  it.effect("should test success path", () =>
    Effect.gen(function* () {
      const result = yield* operation(validInput)
      assert.strictEqual(result.status, "success")
    })
  )

  it.effect("should test validation errors", () =>
    Effect.gen(function* () {
      const error = yield* operation(invalidInput).pipe(Effect.flip)
      assert.strictEqual(error._tag, "ValidationError")
    })
  )

  it.effect("should test edge cases", () =>
    Effect.gen(function* () {
      const result = yield* operation(edgeCaseInput)
      assert.isDefined(result)
    })
  )

  it.effect("should test boundary conditions", () =>
    Effect.gen(function* () {
      const result = yield* operation(boundaryInput)
      assert.isTrue(result.value >= 0)
    })
  )
})
```

#### Test Error Recovery

```typescript
describe("Error recovery", () => {
  it.effect("should retry on transient errors", () =>
    Effect.gen(function* () {
      let attempts = 0
      
      const unreliableOperation = Effect.gen(function* () {
        attempts++
        if (attempts < 3) {
          return yield* Effect.fail(new TransientError())
        }
        return "success"
      })
      
      const result = yield* unreliableOperation.pipe(
        Effect.retry({
          while: (error) => error._tag === "TransientError",
          times: 5
        })
      )
      
      assert.strictEqual(result, "success")
      assert.strictEqual(attempts, 3)
    })
  )

  it.effect("should use fallback on error", () =>
    Effect.gen(function* () {
      const result = yield* primaryOperation().pipe(
        Effect.catchAll(() => fallbackOperation())
      )
      
      assert.isDefined(result)
    })
  )

  it.effect("should transform errors", () =>
    Effect.gen(function* () {
      const error = yield* operation().pipe(
        Effect.mapError((e) => new ApplicationError({ cause: e })),
        Effect.flip
      )
      
      assert.strictEqual(error._tag, "ApplicationError")
    })
  )
})
```

#### Testing Checklist

Before completing a test suite, ensure:

- [ ] All success paths are tested
- [ ] All error cases are covered
- [ ] Edge cases and boundary conditions tested
- [ ] Time-dependent code uses TestClock
- [ ] External dependencies are mocked
- [ ] Error recovery mechanisms tested
- [ ] Concurrency is tested appropriately
- [ ] Tests use @effect/vitest for Effect code
- [ ] Tests use assert methods, not expect
- [ ] Tests provide necessary layers
- [ ] Tests focus on business value
- [ ] Tests are deterministic (no flakiness)
- [ ] Tests are fast (proper use of TestClock)
- [ ] Integration tests cover critical paths

---

**Summary**: Testing Effect code requires understanding framework selection (@effect/vitest vs vitest), using it.effect with assert methods, leveraging TestClock for time-dependent tests, creating mock layers for dependencies, and focusing on business behavior rather than implementation details. Always test all paths including success, errors, and edge cases while ensuring tests remain fast, deterministic, and focused on value.
