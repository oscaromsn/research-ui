## 6. Concurrency & Asynchronicity

### 6.1 Parallel Execution

#### Effect.all - Concurrent Execution

`Effect.all` is the primary primitive for running multiple effects concurrently:

```typescript
import { Effect } from "effect"

// Basic parallel execution
const getUserData = (userId: string) =>
  Effect.gen(function* () {
    // All three operations run in parallel
    const [user, orders, preferences] = yield* Effect.all([
      userService.getUser(userId),
      orderService.getUserOrders(userId),
      preferenceService.getUserPreferences(userId)
    ])

    return { user, orders, preferences }
  })

// With explicit concurrency setting
const fetchAllUsers = (userIds: string[]) =>
  Effect.all(
    userIds.map(id => fetchUser(id)),
    { concurrency: "unbounded" } // No limit on concurrent operations
  )
```

#### Concurrency Options

Effect.all supports three concurrency modes:

```typescript
// Unbounded - all operations run concurrently
Effect.all(effects, { concurrency: "unbounded" })

// Limited - maximum N concurrent operations
Effect.all(effects, { concurrency: 5 })

// Inherit - use parent scope's concurrency setting
Effect.all(effects, { concurrency: "inherit" })
```

**Decision Matrix:**

| Scenario | Concurrency Setting | Reasoning |
|----------|-------------------|-----------|
| Independent HTTP requests | `"unbounded"` | Network I/O, not CPU-bound |
| CPU-intensive operations | `5-10` | Limit based on available cores |
| Database queries | `10-20` | Based on connection pool size |
| Rate-limited API calls | `1-3` | Respect API limits |
| File I/O operations | `"unbounded"` | OS handles I/O scheduling |

#### Effect.forEach - Iterative Concurrent Processing

Process collections with concurrent control:

```typescript
import { Effect } from "effect"

// Process items with concurrency limit
const processUsers = (userIds: string[]) =>
  Effect.forEach(
    userIds,
    (id) => processUser(id),
    { concurrency: 5 } // Process 5 at a time
  )

// With batching optimization
const batchProcessOrders = (orderIds: string[]) =>
  Effect.forEach(
    orderIds,
    (id) => processOrder(id),
    {
      concurrency: 10,
      batching: true // Optimize for batch operations
    }
  )

// Discard results for side-effects only
const sendNotifications = (userIds: string[]) =>
  Effect.forEach(
    userIds,
    (id) => sendNotification(id),
    {
      concurrency: "unbounded",
      discard: true // Don't collect results
    }
  )
```

#### Array Operations with Concurrency

Leverage Effect's concurrent array operations:

```typescript
import { Effect, Array as Arr } from "effect"

// Parallel map
const enrichUsers = (users: User[]) =>
  Effect.all(
    users.map(user => enrichUserData(user)),
    { concurrency: "unbounded" }
  )

// Concurrent filter with effectful predicate
const activeUsers = (users: User[]) =>
  Effect.gen(function* () {
    const results = yield* Effect.all(
      users.map(user =>
        isUserActive(user).pipe(
          Effect.map(active => ({ user, active }))
        )
      ),
      { concurrency: "unbounded" }
    )

    return results
      .filter(r => r.active)
      .map(r => r.user)
  })
```

#### Race Conditions and Ordering

```typescript
// ✅ CORRECT: Effects run concurrently, results collected in order
const orderedResults = yield* Effect.all([
  slowOperation(),  // Takes 3 seconds
  fastOperation(),  // Takes 1 second
  mediumOperation() // Takes 2 seconds
])
// Results: [slow, fast, medium] - always in original order

// ❌ AVOID: Manual fiber management for simple parallel operations
const manualParallel = Effect.gen(function* () {
  const fiber1 = yield* Effect.fork(operation1())
  const fiber2 = yield* Effect.fork(operation2())
  const fiber3 = yield* Effect.fork(operation3())

  const result1 = yield* Fiber.join(fiber1)
  const result2 = yield* Fiber.join(fiber2)
  const result3 = yield* Fiber.join(fiber3)

  return [result1, result2, result3]
})

// ✅ PREFER: High-level API is cleaner and safer
const cleanParallel = Effect.all([
  operation1(),
  operation2(),
  operation3()
], { concurrency: "unbounded" })
```

### 6.2 Fiber Management

#### Effect.fork - Creating Fibers

Fibers are lightweight threads managed by Effect runtime:

```typescript
import { Effect, Fiber } from "effect"

// Basic fiber creation
const backgroundWork = Effect.gen(function* () {
  // Fork returns a Fiber handle
  const fiber = yield* Effect.fork(
    longRunningTask()
  )

  // Do other work while task runs in background
  yield* someOtherWork()

  // Wait for fiber to complete
  const result = yield* Fiber.join(fiber)

  return result
})

// Multiple concurrent fibers
const parallelWork = Effect.gen(function* () {
  const fiber1 = yield* Effect.fork(task1())
  const fiber2 = yield* Effect.fork(task2())
  const fiber3 = yield* Effect.fork(task3())

  // Wait for all to complete
  const results = yield* Effect.all([
    Fiber.join(fiber1),
    Fiber.join(fiber2),
    Fiber.join(fiber3)
  ])

  return results
})
```

#### Fiber.join - Waiting for Completion

```typescript
// Join waits for fiber completion and returns result
const withJoin = Effect.gen(function* () {
  const fiber = yield* Effect.fork(fetchData())

  yield* doOtherWork()

  // Blocks until fiber completes, propagates errors
  const data = yield* Fiber.join(fiber)

  return data
})

// Joining multiple fibers
const joinMultiple = Effect.gen(function* () {
  const fibers = yield* Effect.all([
    Effect.fork(task1()),
    Effect.fork(task2()),
    Effect.fork(task3())
  ])

  const results = yield* Effect.all(
    fibers.map(fiber => Fiber.join(fiber))
  )

  return results
})
```

#### Effect.forkDaemon - Daemon Fibers

Daemon fibers outlive their parent scope:

```typescript
// Regular fork - fiber dies when parent interrupted
const regularFork = Effect.gen(function* () {
  const fiber = yield* Effect.fork(backgroundTask())
  // If this effect is interrupted, fiber is interrupted too
})

// Daemon fork - fiber continues even if parent interrupted
const daemonFork = Effect.gen(function* () {
  const fiber = yield* Effect.forkDaemon(backgroundTask())
  // Fiber continues even if this effect is interrupted
})

// ⚠️ CRITICAL: Daemon fibers must be managed explicitly
const managedDaemon = Effect.gen(function* () {
  const fiber = yield* Effect.forkDaemon(longRunningTask())

  // Ensure cleanup
  yield* Effect.addFinalizer(() =>
    Fiber.interrupt(fiber).pipe(Effect.orDie)
  )

  return fiber
})

// ✅ PREFER: Scoped resources over daemon fibers
const scopedResource = Effect.gen(function* () {
  const resource = yield* Effect.acquireRelease(
    openResource(),
    (r) => closeResource(r)
  )

  return resource
})
```

#### Structured Concurrency

Effect provides automatic parent-child fiber lifecycle management:

```typescript
// Parent-child relationship
const structuredConcurrency = Effect.gen(function* () {
  // Parent fiber
  const parentFiber = yield* Effect.fork(
    Effect.gen(function* () {
      // Child fiber
      const childFiber = yield* Effect.fork(childTask())

      yield* parentTask()

      // If parent is interrupted, child is automatically interrupted
      yield* Fiber.join(childFiber)
    })
  )

  yield* Fiber.join(parentFiber)
})

// Interruption propagates down the fiber tree
const interruption = Effect.gen(function* () {
  const fiber = yield* Effect.fork(
    Effect.gen(function* () {
      const child1 = yield* Effect.fork(task1())
      const child2 = yield* Effect.fork(task2())
      const child3 = yield* Effect.fork(task3())

      // All children automatically interrupted when parent is
      yield* Effect.never // Wait indefinitely
    })
  )

  yield* Effect.sleep("1 second")

  // Interrupts parent AND all children
  yield* Fiber.interrupt(fiber)
})
```

#### When to Use Manual Fiber Management

**✅ Use Effect.fork when:**
- You need fine-grained control over fiber lifecycle
- Building low-level concurrency abstractions
- Implementing custom coordination patterns
- Monitoring long-running background operations

**❌ Avoid Effect.fork when:**
- `Effect.all` or `Effect.race` can solve the problem
- You don't need the fiber handle
- Simple parallel execution is sufficient
- You're not handling interruption properly

```typescript
// ❌ BAD: Unnecessary manual fiber management
const unnecessary = Effect.gen(function* () {
  const fiber1 = yield* Effect.fork(fetchUser())
  const fiber2 = yield* Effect.fork(fetchOrders())

  const user = yield* Fiber.join(fiber1)
  const orders = yield* Fiber.join(fiber2)

  return { user, orders }
})

// ✅ GOOD: High-level API is clearer and safer
const better = Effect.gen(function* () {
  const [user, orders] = yield* Effect.all([
    fetchUser(),
    fetchOrders()
  ])

  return { user, orders }
})
```

### 6.3 Racing & Timeouts

#### Effect.race - First Success Wins

```typescript
import { Effect } from "effect"

// Basic race - returns first successful result
const getUserFromMultipleSources = (id: string) =>
  Effect.race(
    primaryDatabase.getUser(id),
    backupDatabase.getUser(id)
  )

// Race multiple effects
const firstAvailable = Effect.raceAll([
  primaryApi.fetch(),
  secondaryApi.fetch(),
  tertiaryApi.fetch()
])

// Race with fallback chain
const withFallbacks = Effect.gen(function* () {
  return yield* Effect.race(
    fastButUnreliable(),
    slowButReliable()
  )
})
```

#### Effect.timeout - Time Limits

```typescript
// Timeout returns Option - None if timeout occurs
const withTimeout = (id: string) =>
  getUserData(id).pipe(
    Effect.timeout("5 seconds")
  )

// Usage with Option handling
const handleTimeout = Effect.gen(function* () {
  const result = yield* fetchData().pipe(
    Effect.timeout("3 seconds")
  )

  if (result._tag === "None") {
    // Timeout occurred
    return yield* Effect.fail(new TimeoutError())
  }

  return result.value
})

// Timeout with default value
const withDefault = fetchData().pipe(
  Effect.timeout("5 seconds"),
  Effect.map(option =>
    option._tag === "Some" ? option.value : defaultValue
  )
)

// Alternative: Use timeoutFail to fail directly
const failOnTimeout = fetchData().pipe(
  Effect.timeoutFail({
    duration: "5 seconds",
    onTimeout: () => new TimeoutError({ operation: "fetchData" })
  })
)
```

#### Racing with Timeout Pattern

```typescript
// Combine race and timeout for resilient operations
const resilientFetch = (id: string) =>
  Effect.race(
    primaryApi.fetch(id),
    secondaryApi.fetch(id)
  ).pipe(
    Effect.timeout("10 seconds"),
    Effect.flatMap(option =>
      option._tag === "Some"
        ? Effect.succeed(option.value)
        : Effect.fail(new TimeoutError())
    )
  )

// Race against timeout
const raceTimeout = Effect.race(
  longRunningOperation(),
  Effect.sleep("30 seconds").pipe(
    Effect.flatMap(() => Effect.fail(new TimeoutError()))
  )
)
```

#### Effect.raceAll - Multiple Effect Racing

```typescript
// First success from multiple sources
const firstSuccess = Effect.raceAll([
  fetchFromCache(),
  fetchFromDatabase(),
  fetchFromApi()
])

// With error handling
const resilientFetch = Effect.raceAll([
  primarySource.fetch(),
  secondarySource.fetch(),
  fallbackSource.fetch()
]).pipe(
  Effect.timeout("10 seconds"),
  Effect.catchAll(() => Effect.succeed(defaultValue))
)
```

### 6.4 Interruption

#### Interruption Safety with Effect.ensuring

```typescript
import { Effect } from "effect"

// Ensuring cleanup always runs
const safeOperation = Effect.gen(function* () {
  yield* Effect.log("Starting operation")

  yield* longRunningTask().pipe(
    Effect.ensuring(
      Effect.log("Cleanup: Operation ended") // Always runs
    )
  )

  yield* Effect.log("Operation completed")
})

// Multiple cleanup handlers
const multipleCleanups = Effect.gen(function* () {
  yield* operation().pipe(
    Effect.ensuring(cleanup1()),
    Effect.ensuring(cleanup2()),
    Effect.ensuring(cleanup3())
  )
  // Cleanups run in reverse order: cleanup3, cleanup2, cleanup1
})
```

#### Uninterruptible Regions

```typescript
// Critical sections that cannot be interrupted
const criticalSection = Effect.gen(function* () {
  yield* Effect.log("Before critical section")

  // This block cannot be interrupted
  yield* Effect.uninterruptible(
    Effect.gen(function* () {
      yield* updateDatabase()
      yield* updateCache()
      yield* sendNotification()
    })
  )

  yield* Effect.log("After critical section")
})

// Interruptible again after uninterruptible region
const mixedRegions = Effect.gen(function* () {
  // Interruptible
  yield* step1()

  // Uninterruptible
  yield* Effect.uninterruptible(step2())

  // Interruptible again
  yield* step3()
})
```

#### Handling Interruption

```typescript
// Detect and handle interruption
const handleInterruption = Effect.gen(function* () {
  yield* longOperation().pipe(
    Effect.onInterrupt(() =>
      Effect.log("Operation was interrupted, cleaning up...")
    )
  )
})

// Graceful shutdown pattern
const gracefulShutdown = Effect.gen(function* () {
  const shutdown = yield* Deferred.make<void>()

  const worker = Effect.gen(function* () {
    while (true) {
      yield* processNextItem().pipe(
        Effect.race(Deferred.await(shutdown))
      )
    }
  }).pipe(
    Effect.ensuring(
      Effect.log("Worker shutting down gracefully")
    )
  )

  const fiber = yield* Effect.fork(worker)

  // Trigger shutdown
  yield* Deferred.succeed(shutdown, undefined)
  yield* Fiber.join(fiber)
})
```

#### Interruption Propagation

```typescript
// Parent interruption propagates to children
const parentChild = Effect.gen(function* () {
  const parent = yield* Effect.fork(
    Effect.gen(function* () {
      const child = yield* Effect.fork(
        Effect.sleep("10 seconds").pipe(
          Effect.ensuring(Effect.log("Child cleanup"))
        )
      )

      yield* Effect.sleep("5 seconds").pipe(
        Effect.ensuring(Effect.log("Parent cleanup"))
      )

      yield* Fiber.join(child)
    })
  )

  yield* Effect.sleep("2 seconds")

  // Interrupts both parent and child
  yield* Fiber.interrupt(parent)
})

// Manual interruption
const manualInterrupt = Effect.gen(function* () {
  const fiber = yield* Effect.fork(longRunningTask())

  yield* Effect.sleep("5 seconds")

  // Explicitly interrupt
  yield* Fiber.interrupt(fiber)
})
```

#### Testing Interruption

```typescript
// Test that cleanup happens on interruption
it.effect("handles interruption gracefully", () =>
  Effect.gen(function* () {
    let cleanupCalled = false

    const task = Effect.sleep("1 second").pipe(
      Effect.ensuring(
        Effect.sync(() => { cleanupCalled = true })
      )
    )

    const fiber = yield* Effect.fork(task)
    yield* Effect.sleep("100 millis")
    yield* Fiber.interrupt(fiber)

    assert.isTrue(cleanupCalled)
  })
)
```

### 6.5 Synchronization Primitives

#### Primitive Selection Guide

| Scenario | Primitive | Use Case |
|----------|-----------|----------|
| **Mutual exclusion** | `Semaphore(1)` | Ensure only one operation at a time |
| **Limited concurrency** | `Semaphore(N)` | Limit concurrent access to N operations |
| **Gating/pausing** | `Latch` | Block fibers until event occurs |
| **Observable state** | `SubscriptionRef` | Reactive state with change notifications |
| **Simple state** | `Ref` | Thread-safe mutable state |
| **Message passing** | `Queue` or `Hub` | Producer-consumer patterns |
| **One-time values** | `Deferred` | One-to-one async result |

#### Semaphore - Rate Limiting and Mutual Exclusion

```typescript
import { Effect, Semaphore } from "effect"

// Mutex (mutual exclusion) - only one operation at a time
const withMutex = Effect.gen(function* () {
  const mutex = yield* Semaphore.make(1)

  const criticalSection = mutex.withPermits(1)(
    Effect.gen(function* () {
      // Only one fiber can execute this at a time
      yield* updateSharedResource()
    })
  )

  // Multiple concurrent calls, but only one executes at a time
  yield* Effect.all([
    criticalSection,
    criticalSection,
    criticalSection
  ], { concurrency: "unbounded" })
})

// Rate limiting - limit concurrent access
const rateLimit = Effect.gen(function* () {
  const semaphore = yield* Semaphore.make(5) // Max 5 concurrent

  const items = Array.from({ length: 100 }, (_, i) => i)

  yield* Effect.forEach(
    items,
    (item) => semaphore.withPermits(1)(processItem(item)),
    { concurrency: "unbounded" } // Semaphore controls actual concurrency
  )
})

// Token refresh synchronization example
const tokenRefresh = Effect.gen(function* () {
  const refreshSemaphore = yield* Semaphore.make(1)

  const refresh = refreshSemaphore.withPermits(1)(
    Effect.gen(function* () {
      yield* Effect.log("Refreshing token...")
      const newToken = yield* fetchNewToken()
      yield* saveToken(newToken)
      return newToken
    })
  )

  // Multiple concurrent calls, but only one refresh happens
  yield* Effect.all([
    refresh,
    refresh,
    refresh
  ], { concurrency: "unbounded" })
})
```

#### Queue - Producer-Consumer Pattern

```typescript
import { Effect, Queue } from "effect"

// Basic queue usage
const producerConsumer = Effect.gen(function* () {
  const queue = yield* Queue.bounded<string>(100)

  // Producer
  const producer = Effect.gen(function* () {
    for (let i = 0; i < 1000; i++) {
      yield* Queue.offer(queue, `item-${i}`)
    }
    yield* Queue.shutdown(queue) // Signal completion
  })

  // Consumer
  const consumer = Effect.gen(function* () {
    while (true) {
      const item = yield* Queue.take(queue)
      yield* processItem(item)
    }
  }).pipe(
    Effect.catchTag("QueueShutdown", () => Effect.void)
  )

  // Multiple consumers
  const consumers = Effect.all([
    Effect.fork(consumer),
    Effect.fork(consumer),
    Effect.fork(consumer)
  ])

  // Run
  yield* Effect.fork(producer)
  const consumerFibers = yield* consumers
  yield* Effect.all(consumerFibers.map(Fiber.join))
})

// Bounded vs unbounded queues
const boundedQueue = Queue.bounded<Task>(10)   // Max 10 items
const unboundedQueue = Queue.unbounded<Task>() // No limit

// Queue operations
const queueOps = Effect.gen(function* () {
  const queue = yield* Queue.bounded<number>(5)

  // Offer (blocks if full)
  yield* Queue.offer(queue, 42)

  // Take (blocks if empty)
  const item = yield* Queue.take(queue)

  // Size
  const size = yield* Queue.size(queue)

  // Shutdown
  yield* Queue.shutdown(queue)
})
```

#### Deferred - One-Time Promises

```typescript
import { Effect, Deferred } from "effect"

// Basic Deferred usage
const coordinatedWork = Effect.gen(function* () {
  const deferred = yield* Deferred.make<string>()

  // Fiber 1: Waits for value
  const waiter = Effect.gen(function* () {
    yield* Effect.log("Waiting for value...")
    const value = yield* Deferred.await(deferred)
    yield* Effect.log(`Received: ${value}`)
    return value
  })

  // Fiber 2: Provides value
  const provider = Effect.gen(function* () {
    yield* Effect.sleep("1 second")
    yield* Deferred.succeed(deferred, "Hello!")
  })

  const fiber1 = yield* Effect.fork(waiter)
  const fiber2 = yield* Effect.fork(provider)

  yield* Fiber.join(fiber1)
  yield* Fiber.join(fiber2)
})

// Deferred can only be completed once
const onceOnly = Effect.gen(function* () {
  const deferred = yield* Deferred.make<number>()

  yield* Deferred.succeed(deferred, 42)
  yield* Deferred.succeed(deferred, 100) // Has no effect

  const value = yield* Deferred.await(deferred)
  // value is 42
})

// Deferred with failure
const deferredError = Effect.gen(function* () {
  const deferred = yield* Deferred.make<number, MyError>()

  yield* Deferred.fail(deferred, new MyError())

  const result = yield* Deferred.await(deferred).pipe(Effect.either)
  // result is Left(MyError)
})
```

#### Latch - Gating Operations

```typescript
import { Effect, Latch } from "effect"

// Basic latch usage
const withLatch = Effect.gen(function* () {
  const latch = yield* Latch.make(false) // Starts closed

  // Operations wait for latch to open
  const operation = Effect.gen(function* () {
    yield* Latch.await(latch)
    yield* performWork()
  })

  // Start multiple operations
  const fibers = yield* Effect.all([
    Effect.fork(operation),
    Effect.fork(operation),
    Effect.fork(operation)
  ])

  yield* Effect.sleep("1 second")

  // Open latch - all waiting operations proceed
  yield* Latch.open(latch)

  yield* Effect.all(fibers.map(Fiber.join))
})

// Initialization gate pattern
const initializationGate = Effect.gen(function* () {
  const initLatch = yield* Latch.make(false)

  // Operations block until initialization completes
  const protectedOperation = Latch.await(initLatch).pipe(
    Effect.andThen(actualWork())
  )

  // Initialize system
  yield* initialize().pipe(
    Effect.ensuring(Latch.open(initLatch)) // CRITICAL: Always open latch
  )

  // Now operations can proceed
  yield* protectedOperation
})

// Multiple latches for staged initialization
const stagedInit = Effect.gen(function* () {
  const dbReady = yield* Latch.make(false)
  const cacheReady = yield* Latch.make(false)

  // Stage 1: Database
  yield* initializeDatabase().pipe(
    Effect.ensuring(Latch.open(dbReady))
  )

  // Stage 2: Cache (waits for database)
  yield* Latch.await(dbReady)
  yield* initializeCache().pipe(
    Effect.ensuring(Latch.open(cacheReady))
  )

  // Stage 3: Application (waits for both)
  yield* Latch.await(cacheReady)
  yield* startApplication()
})
```

#### Ref - Thread-Safe State

```typescript
import { Effect, Ref } from "effect"

// Basic Ref usage
const counter = Effect.gen(function* () {
  const ref = yield* Ref.make(0)

  // Atomic update
  yield* Ref.update(ref, (n) => n + 1)

  // Atomic get and update
  const oldValue = yield* Ref.getAndUpdate(ref, (n) => n + 1)

  // Get current value
  const current = yield* Ref.get(ref)

  return current
})

// Atomic operations are guaranteed
const atomicCounter = Effect.gen(function* () {
  const ref = yield* Ref.make(0)

  // 100 concurrent increments
  yield* Effect.all(
    Array.from({ length: 100 }, () =>
      Ref.update(ref, (n) => n + 1)
    ),
    { concurrency: "unbounded" }
  )

  const final = yield* Ref.get(ref)
  // final is always 100, guaranteed
})

// Complex state updates
interface State {
  readonly count: number
  readonly lastUpdated: Date
}

const complexState = Effect.gen(function* () {
  const ref = yield* Ref.make<State>({
    count: 0,
    lastUpdated: new Date()
  })

  yield* Ref.update(ref, (state) => ({
    count: state.count + 1,
    lastUpdated: new Date()
  }))
})

// Conditional updates with Ref.modify
const conditionalUpdate = Effect.gen(function* () {
  const ref = yield* Ref.make(0)

  // Returns [return value, new state]
  const result = yield* Ref.modify(ref, (n) =>
    n < 10
      ? [true, n + 1]  // Update if less than 10
      : [false, n]     // Don't update otherwise
  )

  return result
})
```

#### SubscriptionRef - Observable State

```typescript
import { Effect, SubscriptionRef, Stream } from "effect"

// SubscriptionRef for reactive state
const reactiveState = Effect.gen(function* () {
  const tokens = yield* SubscriptionRef.make<Option.Option<Tokens>>(
    Option.none()
  )

  // Subscribe to changes
  const subscriber = tokens.changes.pipe(
    Stream.runForEach((token) =>
      Effect.log(`Token updated: ${token}`)
    )
  ).pipe(Effect.forkDaemon)

  // Updates automatically notify subscribers
  yield* SubscriptionRef.set(tokens, Option.some(newTokens))

  // All subscribers receive notification
})

// Multiple subscribers
const multipleSubscribers = Effect.gen(function* () {
  const state = yield* SubscriptionRef.make(0)

  // Subscriber 1
  const sub1 = state.changes.pipe(
    Stream.runForEach((value) =>
      Effect.log(`Subscriber 1: ${value}`)
    )
  ).pipe(Effect.forkDaemon)

  // Subscriber 2
  const sub2 = state.changes.pipe(
    Stream.runForEach((value) =>
      Effect.log(`Subscriber 2: ${value}`)
    )
  ).pipe(Effect.forkDaemon)

  // Update state - both subscribers notified
  yield* SubscriptionRef.set(state, 42)
})

// Use for token refresh pattern
const tokenManager = Effect.gen(function* () {
  const tokens = yield* SubscriptionRef.make<Option.Option<Tokens>>(
    Option.none()
  )

  const refreshSemaphore = yield* Semaphore.make(1)

  const refresh = refreshSemaphore.withPermits(1)(
    Effect.gen(function* () {
      const newTokens = yield* fetchNewTokens()
      yield* SubscriptionRef.set(tokens, Option.some(newTokens))
      return newTokens
    })
  )

  const getToken = Effect.gen(function* () {
    const current = yield* SubscriptionRef.get(tokens)

    if (Option.isNone(current)) {
      return yield* refresh
    }

    return current.value
  })

  return { refresh, getToken } as const
})
```

### 6.6 High-Level Concurrency

#### Prefer High-Level APIs

**✅ ALWAYS prefer:**
- `Effect.all` over manual `Effect.fork` + `Fiber.join`
- `Effect.forEach` over loops with `Effect.fork`
- `Effect.race` over manual fiber racing

#### Concurrency Control Strategies

```typescript
// Control concurrency to prevent resource exhaustion
const controlled = Effect.gen(function* () {
  const items = Array.from({ length: 10000 }, (_, i) => i)

  // ❌ BAD: Unbounded concurrency for many items
  yield* Effect.all(
    items.map(processItem),
    { concurrency: "unbounded" } // May exhaust resources
  )

  // ✅ GOOD: Bounded concurrency
  yield* Effect.all(
    items.map(processItem),
    { concurrency: 50 } // Processes 50 at a time
  )
})

// Adaptive concurrency based on resource availability
const adaptive = Effect.gen(function* () {
  const availableCores = navigator.hardwareConcurrency || 4
  const concurrency = Math.max(2, availableCores - 1)

  yield* Effect.forEach(
    items,
    processItem,
    { concurrency }
  )
})
```

#### Backpressure Handling

```typescript
// Queue-based backpressure
const withBackpressure = Effect.gen(function* () {
  const queue = yield* Queue.bounded<Task>(100) // Buffer size

  // Producer respects queue capacity
  const producer = Effect.gen(function* () {
    for (const item of largeDataset) {
      yield* Queue.offer(queue, item) // Blocks when full
    }
  })

  // Consumer processes at its own pace
  const consumer = Effect.gen(function* () {
    while (true) {
      const task = yield* Queue.take(queue)
      yield* processTask(task)
    }
  })

  yield* Effect.all([
    Effect.fork(producer),
    Effect.fork(consumer)
  ])
})
```

#### Concurrency Decision Matrix

| Goal | Pattern | Concurrency Setting |
|------|---------|-------------------|
| **Maximum throughput** | `Effect.all` | `"unbounded"` |
| **Respect rate limits** | `Semaphore` + `Effect.forEach` | Match API limit |
| **CPU-bound work** | `Effect.all` | CPU core count |
| **Database queries** | `Effect.all` | Connection pool size |
| **Memory-intensive** | `Effect.all` | Based on available memory |
| **I/O operations** | `Effect.all` | `"unbounded"` |
| **Controlled batching** | `Effect.forEach` | Small constant (5-20) |

#### Anti-Patterns to Avoid

```typescript
// ❌ NEVER: Use global mutable state
let globalCounter = 0
const bad = Effect.sync(() => {
  globalCounter++ // Race condition!
})

// ✅ ALWAYS: Use Ref for shared state
const good = Effect.gen(function* () {
  const counter = yield* Ref.make(0)
  yield* Ref.update(counter, (n) => n + 1) // Thread-safe
})

// ❌ NEVER: Ignore fiber handles without cleanup
const leaked = Effect.gen(function* () {
  yield* Effect.forkDaemon(infiniteLoop())
  // Fiber never cleaned up!
})

// ✅ ALWAYS: Clean up daemon fibers
const cleaned = Effect.gen(function* () {
  const fiber = yield* Effect.forkDaemon(longRunning())
  yield* Effect.addFinalizer(() => Fiber.interrupt(fiber))
})

// ❌ NEVER: Use try-catch for concurrency coordination
const tryWrong = Effect.gen(function* () {
  try {
    yield* riskyOperation()
  } catch {
    // This doesn't work in Effect!
  }
})

// ✅ ALWAYS: Use Effect error handling
const errorRight = Effect.gen(function* () {
  yield* riskyOperation().pipe(
    Effect.catchAll(handleError)
  )
})
```

#### Best Practices Summary

1. **High-Level First**: Always try `Effect.all`, `Effect.forEach`, `Effect.race` before manual fibers
2. **Specify Concurrency**: Always set explicit concurrency limits to prevent resource exhaustion
3. **Handle Interruption**: Use `Effect.ensuring` for cleanup guarantees
4. **Structured Concurrency**: Leverage parent-child fiber relationships
5. **Right Primitive**: Choose the appropriate synchronization primitive (Semaphore, Queue, Ref, Latch, Deferred)
6. **Monitor Fibers**: Track long-running fibers and ensure cleanup
7. **Test Concurrency**: Write tests for concurrent scenarios and interruption
8. **Avoid Blocking**: Never block Effect fibers; use async primitives
9. **Backpressure**: Implement backpressure for producer-consumer patterns
10. **Measure Performance**: Profile before optimizing concurrency settings
