# 5. Service Architecture

## 5.1 Service Definition Patterns

### Modern Effect.Service Pattern (Recommended)

The modern approach uses class-based service definitions with `Effect.Service`, which provides cleaner syntax and automatic layer generation.

```typescript
import { Effect, Layer } from "effect"

// ✅ MODERN PATTERN: Class-based service with Effect.Service
export class EmailService extends Effect.Service<EmailService>()(
  "app/EmailService",
  {
    // Specify dependencies
    dependencies: [SmtpClient.Default],
    
    // Use scoped for resources that need cleanup
    scoped: Effect.gen(function* () {
      const smtp = yield* SmtpClient
      const logger = yield* Logger
      
      return {
        send: (to: string, body: string) =>
          smtp.send({ to, body }).pipe(
            Effect.catchAll((error) =>
              Effect.fail(new SendError({ to, reason: error.message }))
            )
          ),
        
        sendBulk: (recipients: string[], body: string) =>
          Effect.all(
            recipients.map(to => this.send(to, body)),
            { concurrency: 10 }
          )
      } as const
    })
  }
) {}

// Usage: EmailService.Default provides the default layer
```

**Benefits:**
- Automatic `ServiceName.Default` layer generation
- Cleaner, more concise syntax
- Built-in dependency declaration
- Type-safe service interface

### Context.Tag Pattern (Type-First Approach)

Use `Context.Tag` when you need to define the interface before implementation, or when there's no sensible default implementation.

```typescript
import { Context, Effect, Layer } from "effect"

// ✅ TYPE-FIRST PATTERN: Interface before implementation
export class UserRepository extends Context.Tag("@app/UserRepository")
  UserRepository,
  {
    readonly findById: (id: string) => Effect.Effect<User, UserNotFound>
    readonly save: (user: User) => Effect.Effect<void, DatabaseError>
    readonly delete: (id: string) => Effect.Effect<void, DatabaseError>
  }
>() {}

// Separate layer creation
export const UserRepositoryLive = Layer.effect(
  UserRepository,
  Effect.gen(function* () {
    const db = yield* Database
    
    return {
      findById: (id) =>
        db.query(`SELECT * FROM users WHERE id = ?`, [id]).pipe(
          Effect.flatMap((result) =>
            result 
              ? Effect.succeed(parseUser(result))
              : Effect.fail(new UserNotFound({ id }))
          )
        ),
      
      save: (user) =>
        db.query(`INSERT INTO users VALUES (?, ?)`, [user.id, user.name]),
      
      delete: (id) =>
        db.query(`DELETE FROM users WHERE id = ?`, [id])
    }
  })
)
```

**When to use:**
- No sensible default implementation
- Contextual services (different implementations per context)
- Legacy code compatibility
- When interface definition should precede implementation

### Service Interface Design

**Core principles for service interfaces:**

```typescript
// ✅ CORRECT: Well-designed service interface
export class ProductService extends Effect.Service<ProductService>()(
  "app/ProductService",
  {
    effect: Effect.gen(function* () {
      const db = yield* Database
      
      return {
        // Readonly methods
        readonly getById: (id: string) => 
          Effect.Effect<Product, ProductNotFound | DatabaseError>,
        
        // Effect return types (never Promise or void)
        readonly create: (data: CreateProductData) => 
          Effect.Effect<Product, ValidationError | DatabaseError>,
        
        // Explicit error types in signature
        readonly update: (id: string, data: UpdateProductData) => 
          Effect.Effect<Product, ProductNotFound | ValidationError | DatabaseError>,
        
        // Explicit dependency requirements (via context)
        readonly delete: (id: string) => 
          Effect.Effect<void, ProductNotFound | DatabaseError>
      }
    })
  }
) {}
```

**Anti-patterns to avoid:**

```typescript
// ❌ BAD: Leaking implementation details
class BadService extends Effect.Service<BadService>()(
  "BadService",
  {
    effect: Effect.gen(function* () {
      return {
        // ❌ Don't return Promises
        getData: async () => fetch("/api/data"),
        
        // ❌ Don't use void for operations that can fail
        save: (data: unknown) => { /* ... */ },
        
        // ❌ Don't expose internal state
        cache: new Map<string, unknown>(),
        
        // ❌ Don't expose Scope in public API
        initialize: Effect.Effect<void, never, Scope.Scope>
      }
    })
  }
) {}
```

### Decision Matrix: Service Definition Pattern

| Use Case | Pattern | Rationale |
|----------|---------|-----------|
| Standard application service | `Effect.Service` | Cleaner syntax, automatic layer |
| Service with clear default | `Effect.Service` | Built-in `ServiceName.Default` |
| Service needing lifecycle | `Effect.Service` with `scoped` | Resource management |
| Type-first design | `Context.Tag` | Define interface before implementation |
| Multiple implementations | `Context.Tag` | No single "default" |
| Contextual services | `Context.Tag` | Different implementations per context |

## 5.2 Service Implementation

### The makeService Pattern

The standard pattern for implementing services uses `Effect.gen` to build the service constructor:

```typescript
// Complete service implementation pattern
export class TodoService extends Effect.Service<TodoService>()(
  "app/TodoService",
  {
    dependencies: [Database.Default, Logger.Default, Cache.Default],
    
    scoped: Effect.gen(function* () {
      // 1. Access dependencies at the top
      const db = yield* Database
      const logger = yield* Logger
      const cache = yield* Cache
      
      // 2. Initialize any local state or resources
      const statsRef = yield* Ref.make({ created: 0, completed: 0 })
      
      // 3. Define internal helper functions
      const updateStats = (type: "created" | "completed") =>
        Ref.update(statsRef, stats => ({
          ...stats,
          [type]: stats[type] + 1
        }))
      
      // 4. Define service methods
      const create = (data: CreateTodoData): Effect.Effect<Todo, ValidationError | DatabaseError> =>
        Effect.gen(function* () {
          yield* logger.debug("Creating todo", { data })
          
          const validated = yield* validateTodoData(data)
          const todo = yield* db.todos.create(validated)
          
          yield* cache.set(`todo:${todo.id}`, todo, { ttl: "5 minutes" })
          yield* updateStats("created")
          
          yield* logger.info("Todo created", { todoId: todo.id })
          
          return todo
        })
      
      const complete = (id: string): Effect.Effect<Todo, TodoNotFound | TodoAlreadyCompleted> =>
        Effect.gen(function* () {
          const todo = yield* db.todos.findById(id).pipe(
            Effect.flatMap((result) =>
              result 
                ? Effect.succeed(result)
                : Effect.fail(new TodoNotFound({ id }))
            )
          )
          
          if (todo.completed) {
            return yield* Effect.fail(new TodoAlreadyCompleted({ id }))
          }
          
          const updated = yield* db.todos.update(id, { completed: true })
          yield* cache.invalidate(`todo:${id}`)
          yield* updateStats("completed")
          
          return updated
        })
      
      const getStats = Ref.get(statsRef)
      
      // 5. Return service interface with 'as const'
      return {
        create,
        complete,
        getStats
      } as const
    })
  }
) {}
```

### Service Dependencies

**Explicit dependency declaration:**

```typescript
export class OrderService extends Effect.Service<OrderService>()(
  "app/OrderService",
  {
    // Declare all dependencies
    dependencies: [
      UserRepository.Default,
      ProductRepository.Default,
      PaymentService.Default,
      EmailService.Default
    ],
    
    effect: Effect.gen(function* () {
      // Access dependencies
      const users = yield* UserRepository
      const products = yield* ProductRepository
      const payments = yield* PaymentService
      const email = yield* EmailService
      
      const createOrder = (userId: string, items: OrderItem[]) =>
        Effect.gen(function* () {
          // Use multiple services
          const user = yield* users.findById(userId)
          const productData = yield* Effect.all(
            items.map(item => products.findById(item.productId))
          )
          
          const total = calculateTotal(items, productData)
          const payment = yield* payments.processPayment(user.id, total)
          
          const order = {
            userId,
            items,
            total,
            paymentId: payment.id,
            createdAt: new Date()
          }
          
          yield* email.send(user.email, formatOrderConfirmation(order))
          
          return order
        })
      
      return { createOrder }
    })
  }
) {}
```

### Service Methods

**Best practices for service methods:**

```typescript
export class UserService extends Effect.Service<UserService>()(
  "app/UserService",
  {
    effect: Effect.gen(function* () {
      const db = yield* Database
      const logger = yield* Logger
      
      return {
        // ✅ GOOD: Effect-returning with explicit errors
        getUser: (id: string): Effect.Effect<User, UserNotFound | DatabaseError> =>
          Effect.gen(function* () {
            yield* logger.debug("Fetching user", { userId: id })
            
            const user = yield* db.users.findById(id).pipe(
              Effect.mapError(cause => new DatabaseError({ cause }))
            )
            
            if (!user) {
              return yield* Effect.fail(new UserNotFound({ id }))
            }
            
            return user
          }),
        
        // ✅ GOOD: Proper logging in services
        createUser: (data: CreateUserData): Effect.Effect<User, ValidationError | DatabaseError> =>
          Effect.gen(function* () {
            yield* logger.info("Creating user", { email: data.email })
            
            const validated = yield* validateUserData(data)
            const user = yield* db.users.create(validated)
            
            yield* logger.info("User created", { userId: user.id })
            
            return user
          }),
        
        // ✅ GOOD: Tracing/observability in service methods
        updateUser: (id: string, updates: UpdateUserData): Effect.Effect<User, UserNotFound | DatabaseError> =>
          Effect.gen(function* () {
            const user = yield* db.users.update(id, updates)
            return user
          }).pipe(
            Effect.withSpan("user.update", {
              attributes: { userId: id }
            })
          )
      }
    })
  }
) {}
```

## 5.3 Layer System

### Layer Creation

**Core layer creation patterns:**

```typescript
import { Effect, Layer } from "effect"

// 1. Layer.effect - Most common pattern
export const DatabaseLive = Layer.effect(
  Database,
  Effect.gen(function* () {
    const config = yield* Config
    
    return {
      query: (sql: string) => Effect.promise(() => executeQuery(sql))
    }
  })
)

// 2. Layer.succeed - For simple, static implementations
export const MockDatabase = Layer.succeed(
  Database,
  {
    query: (sql) => Effect.succeed({ rows: [] })
  }
)

// 3. Layer.sync - For synchronous initialization
export const ConfigLive = Layer.sync(
  Config,
  () => ({
    apiKey: process.env.API_KEY!,
    baseUrl: process.env.BASE_URL!
  })
)

// 4. Layer.scoped - For resources needing cleanup
export const DatabaseWithPoolLive = Layer.scoped(
  Database,
  Effect.gen(function* () {
    const config = yield* Config
    
    // Acquire resource
    const pool = yield* Effect.acquireRelease(
      Effect.sync(() => createPool(config)),
      (pool) => Effect.sync(() => pool.close())
    )
    
    return {
      query: (sql) => Effect.promise(() => pool.query(sql))
    }
  })
)
```

### Layer Composition

**The single Effect.provide rule:**

```typescript
// ✅ CORRECT: Compose all layers, then provide once
const AppLayer = Layer.mergeAll(
  ConfigLive,
  DatabaseLive,
  CacheLive,
  UserServiceLive,
  EmailServiceLive
)

const program = Effect.gen(function* () {
  const users = yield* UserService
  const result = yield* users.getUser("123")
  return result
})

// Single Effect.provide at application boundary
program.pipe(
  Effect.provide(AppLayer),
  Effect.runPromise
)

// ❌ WRONG: Multiple provide calls break memoization
const broken = program
  .pipe(Effect.provide(DatabaseLive))
  .pipe(Effect.provide(UserServiceLive))  // Creates new scope!
  .pipe(Effect.provide(EmailServiceLive)) // And another!
```

**Layer composition operators:**

```typescript
// Layer.provide - Provide dependency to a layer
const UserServiceWithDb = Layer.provide(
  UserServiceLive,
  DatabaseLive
)

// Layer.merge - Combine independent layers
const DataLayerA = Layer.merge(DatabaseLive, CacheLive)

// Layer.provideMerge - Provide dependencies and merge
const DataLayerB = Layer.provideMerge(
  UserServiceLive,
  Layer.merge(DatabaseLive, CacheLive)
)

// Layer.mergeAll - Merge multiple layers at once
const AppLayer = Layer.mergeAll(
  ConfigLive,
  DatabaseLive,
  CacheLive,
  UserServiceLive
)
```

### Layer Patterns

**Local dependency erasure:**

```typescript
// Create self-contained layer by providing dependencies internally
export const UserServiceComplete = Layer.provideMerge(
  UserServiceLive,
  Layer.mergeAll(
    DatabaseLive,
    CacheLive,
    LoggerLive
  )
)

// Now UserServiceComplete has no external dependencies
// Can be used without providing Database, Cache, Logger
```

**Layer memoization guarantees:**

```typescript
// ✅ Service is created ONCE and shared
const AppLayer = Layer.mergeAll(
  DatabaseLive,      // Created once
  UserServiceLive,   // Created once, receives same Database instance
  ProductServiceLive // Created once, receives same Database instance
)

// Both services share the SAME Database instance
const program = Effect.gen(function* () {
  const users = yield* UserService    // Gets shared Database
  const products = yield* ProductService // Gets shared Database
})
```

### Layer Scope Management

**Understanding layer scope:**

```typescript
// Scoped layers are created when scope begins, cleaned up when scope ends
const withScope = Effect.scoped(
  Effect.gen(function* () {
    // DatabaseLive is scoped, so pool is created here
    const db = yield* Database
    
    yield* db.query("SELECT 1")
    
    // Pool is automatically closed when scope exits
  })
).pipe(Effect.provide(DatabaseLive))

// Multiple provides with scoped layers
const program = Effect.scoped(
  Effect.gen(function* () {
    const db = yield* Database      // Pool created
    const cache = yield* Cache      // Connection created
    
    // Use services...
    
    // Both cleaned up when scope exits
  })
).pipe(
  Effect.provide(Layer.mergeAll(
    DatabaseLive,  // Scoped
    CacheLive      // Scoped
  ))
)
```

## 5.4 Service Design Principles

### Single Responsibility Principle

**Keep services focused:**

```typescript
// ✅ GOOD: Focused services with clear boundaries
export class TokenManager extends Effect.Service<TokenManager>()(
  "app/TokenManager",
  {
    effect: Effect.gen(function* () {
      return {
        refresh: (token: string) => Effect.Effect<Token, TokenError>,
        validate: (token: string) => Effect.Effect<boolean, TokenError>
      }
    })
  }
) {}

export class UserProfile extends Effect.Service<UserProfile>()(
  "app/UserProfile",
  {
    effect: Effect.gen(function* () {
      return {
        get: (userId: string) => Effect.Effect<Profile, ProfileError>,
        update: (userId: string, data: UpdateProfile) => Effect.Effect<Profile, ProfileError>
      }
    })
  }
) {}

// ❌ BAD: Kitchen-sink service with too many responsibilities
export class AuthService extends Effect.Service<AuthService>()(
  "app/AuthService",
  {
    effect: Effect.gen(function* () {
      return {
        login: (credentials: Credentials) => Effect.Effect<Session, AuthError>,
        logout: (sessionId: string) => Effect.Effect<void, AuthError>,
        refresh: (token: string) => Effect.Effect<Token, TokenError>,
        validateToken: (token: string) => Effect.Effect<boolean, TokenError>,
        getUserProfile: (userId: string) => Effect.Effect<Profile, ProfileError>,
        updatePassword: (userId: string, password: string) => Effect.Effect<void, AuthError>,
        resetPassword: (email: string) => Effect.Effect<void, AuthError>,
        sendVerificationEmail: (email: string) => Effect.Effect<void, EmailError>
      }
    })
  }
) {}
```

### Service Extraction Timing

**When to extract a service:**

```typescript
// START SIMPLE: Begin with direct implementation
const processOrder = (orderId: string) =>
  Effect.gen(function* () {
    const pool = yield* createPool()
    const order = yield* pool.query(`SELECT * FROM orders WHERE id = ?`, [orderId])
    return order
  })

// EXTRACT WHEN NEEDED: When you need multiple implementations
export class OrderRepository extends Effect.Service<OrderRepository>()(
  "app/OrderRepository",
  {
    effect: Effect.gen(function* () {
      const pool = yield* createPool()
      
      return {
        findById: (id: string) =>
          pool.query(`SELECT * FROM orders WHERE id = ?`, [id])
      }
    })
  }
) {}

// Now you can provide different implementations
const TestOrderRepository = Layer.succeed(
  OrderRepository,
  {
    findById: (id) => Effect.succeed(mockOrder)
  }
)
```

**Extract services when:**
- ✅ Reuse is required across multiple components
- ✅ Testing requires swapping implementations
- ✅ Multiple implementations needed (different storage backends)
- ✅ Complex initialization or lifecycle management needed

**Don't extract when:**
- ❌ Single use case, no testing requirements
- ❌ Simple, pure functions
- ❌ No state or resources to manage
- ❌ Premature abstraction

### Service Naming Conventions

```typescript
// ✅ GOOD: Globally unique identifiers with namespace
export class UserService extends Effect.Service<UserService>()(
  "@app/UserService",      // Namespace prevents collisions
  { /* ... */ }
) {}

export class EmailService extends Effect.Service<EmailService>()(
  "@app/EmailService",
  { /* ... */ }
) {}

export class DatabaseService extends Effect.Service<DatabaseService>()(
  "@infra/DatabaseService",  // Different namespace for infrastructure
  { /* ... */ }
) {}

// ❌ BAD: Generic names that could collide
export class Service extends Effect.Service<Service>()(
  "Service",  // Too generic
  { /* ... */ }
) {}

export class Data extends Effect.Service<Data>()(
  "Data",  // Could collide with Effect's Data module
  { /* ... */ }
) {}
```

### Service Granularity

**Decision matrix for service size:**

| Indicator | Action |
|-----------|--------|
| > 10 methods | Consider splitting into multiple services |
| Multiple unrelated concerns | Split by domain boundaries |
| Method groups never used together | Split by usage patterns |
| Complex initialization | Keep together, use helpers |
| Shared state | Keep together, encapsulate state |
| Different testing needs | Split by testability requirements |

### Shadow Service Pattern

For tracking calls and assertions:

```typescript
// Shadow service with call tracking
const makeShadowUserService = Effect.gen(function* () {
  const calls = yield* Ref.make<Array<{ method: string; args: unknown[] }>>([])
  
  const trackCall = (method: string, args: unknown[]) =>
    Ref.update(calls, prev => [...prev, { method, args }])
  
  return {
    service: {
      getUser: (id: string) =>
        trackCall("getUser", [id]).pipe(
          Effect.flatMap(() => Effect.succeed({
            id,
            name: "Test User",
            email: "test@example.com"
          }))
        ),
      
      createUser: (data: CreateUserData) =>
        trackCall("createUser", [data]).pipe(
          Effect.flatMap(() => Effect.succeed({
            ...data,
            id: "new-id"
          }))
        )
    },
    
    // Assertion helpers
    getCalls: Ref.get(calls),
    assertCalled: (method: string, times?: number) =>
      Ref.get(calls).pipe(
        Effect.flatMap(callList => {
          const methodCalls = callList.filter(c => c.method === method)
          if (times !== undefined && methodCalls.length !== times) {
            return Effect.fail(
              `Expected ${method} to be called ${times} times, but was called ${methodCalls.length} times`
            )
          }
          return Effect.void
        })
      ),
    
    assertCalledWith: (method: string, expectedArgs: unknown[]) =>
      Ref.get(calls).pipe(
        Effect.flatMap(callList => {
          const call = callList.find(c => c.method === method)
          if (!call) {
            return Effect.fail(`Expected ${method} to be called`)
          }
          // Deep equality check on args...
          return Effect.void
        })
      )
  }
})

// Use in tests
it("tracks service calls", async () => {
  const program = Effect.gen(function* () {
    const shadow = yield* makeShadowUserService
    const service = shadow.service
    
    // Provide shadow service
    yield* Effect.provideService(UserService, service)(
      Effect.gen(function* () {
        const users = yield* UserService
        yield* users.createUser({ name: "John", email: "john@example.com" })
      })
    )
    
    // Assert calls
    yield* shadow.assertCalled("createUser", 1)
    yield* shadow.assertCalledWith("createUser", [
      { name: "John", email: "john@example.com" }
    ])
  })
  
  await Effect.runPromise(program)
})
```

## 5.6 Layered Architecture Patterns

### Three-Layer Pattern (General)

**Standard three-layer architecture for Effect applications:**

```
┌─────────────────────────────┐
│  Handler Layer (HTTP/API)   │  ← Request processing, response formatting
├─────────────────────────────┤
│  Usecase Layer (Business)   │  ← Domain operations, business rules
├─────────────────────────────┤
│  Store Layer (Data Access)  │  ← Database operations, CRUD patterns
└─────────────────────────────┘
```

#### Store Layer (Data Access)

```typescript
// Store layer focuses on data persistence
export class TodoStore extends Effect.Service<TodoStore>()(
  "app/TodoStore",
  {
    dependencies: [Database.Default],
    
    effect: Effect.gen(function* () {
      const db = yield* Database
      
      return {
        getAll: Effect.tryPromise({
          try: () => db.query("SELECT * FROM todos"),
          catch: (error) => new DatabaseError({ operation: "getAll", cause: error })
        }).pipe(
          Effect.map(rows => rows.map(parseTodo))
        ),
        
        getById: (id: string) => Effect.tryPromise({
          try: () => db.query("SELECT * FROM todos WHERE id = ?", [id]),
          catch: (error) => new DatabaseError({ operation: "getById", cause: error })
        }).pipe(
          Effect.flatMap(row =>
            row
              ? Effect.succeed(parseTodo(row))
              : Effect.fail(new RecordNotFound({ table: "todos", id }))
          )
        ),
        
        create: (data: CreateTodoData) => Effect.tryPromise({
          try: () => db.insert("todos", data),
          catch: (error) => new DatabaseError({ operation: "create", cause: error })
        }).pipe(
          Effect.flatMap(id => this.getById(id))
        ),
        
        update: (id: string, updates: UpdateTodoData) =>
          Effect.gen(function* () {
            yield* this.getById(id) // Verify exists
            yield* Effect.tryPromise({
              try: () => db.update("todos", id, updates),
              catch: (error) => new DatabaseError({ operation: "update", cause: error })
            })
            return yield* this.getById(id)
          }),
        
        delete: (id: string) =>
          Effect.gen(function* () {
            yield* this.getById(id) // Verify exists
            yield* Effect.tryPromise({
              try: () => db.delete("todos", id),
              catch: (error) => new DatabaseError({ operation: "delete", cause: error })
            })
          })
      }
    })
  }
) {}
```

#### Usecase Layer (Business Logic)

```typescript
// Usecase layer orchestrates business operations
export class TodoUsecase extends Effect.Service<TodoUsecase>()(
  "app/TodoUsecase",
  {
    dependencies: [TodoStore.Default, Logger.Default],
    
    effect: Effect.gen(function* () {
      const store = yield* TodoStore
      const logger = yield* Logger
      
      return {
        createTodo: (data: CreateTodoData) =>
          Effect.gen(function* () {
            // Validate business rules
            const errors = validateTodoData(data)
            if (errors.length > 0) {
              return yield* Effect.fail(new InvalidTodoData({ errors }))
            }
            
            yield* logger.info("Creating todo", { data })
            
            const todo = yield* store.create(data)
            
            yield* logger.info("Todo created", { todoId: todo.id })
            
            return todo
          }),
        
        completeTodo: (id: string) =>
          Effect.gen(function* () {
            const todo = yield* store.getById(id)
            
            if (todo.completed) {
              return yield* Effect.fail(new TodoAlreadyCompleted({ id }))
            }
            
            return yield* store.update(id, {
              completed: true,
              completedAt: new Date()
            })
          }),
        
        getTodosByUser: (userId: string) =>
          store.getAll().pipe(
            Effect.map(todos => todos.filter(todo => todo.userId === userId))
          )
      }
    })
  }
) {}
```

### Service Cleanup

```typescript
// Proper cleanup in service lifecycle
export class MessageQueueService extends Effect.Service<MessageQueueService>()(
  "app/MessageQueueService",
  {
    scoped: Effect.gen(function* () {
      const config = yield* Config
      const logger = yield* Logger
      
      const connection = yield* Effect.acquireRelease(
        Effect.gen(function* () {
          yield* logger.info("Connecting to message queue")
          return yield* Effect.tryPromise({
            try: () => connectToQueue(config.queue),
            catch: (error) => new QueueConnectionError({ cause: error })
          })
        }),
        (conn) =>
          Effect.gen(function* () {
            yield* logger.info("Closing message queue connection")
            
            // Graceful shutdown: process remaining messages
            yield* Effect.tryPromise({
              try: () => conn.drain(),
              catch: () => Effect.void
            })
            
            // Close connection
            yield* Effect.tryPromise({
              try: () => conn.close(),
              catch: (error) =>
                logger.error("Failed to close queue connection", { error })
            })
          })
      )
      
      // Add finalizer for additional cleanup
      yield* Effect.addFinalizer(() =>
        logger.info("Message queue service cleanup complete")
      )
      
      return {
        publish: (topic: string, message: unknown) =>
          Effect.tryPromise({
            try: () => connection.publish(topic, message),
            catch: (error) => new PublishError({ topic, cause: error })
          }),
        
        subscribe: (topic: string, handler: (msg: unknown) => Effect.Effect<void>) =>
          Effect.tryPromise({
            try: () => connection.subscribe(topic, handler),
            catch: (error) => new SubscribeError({ topic, cause: error })
          })
      }
    })
  }
) {}
```

## Best Practices Summary

### Service Definition
- Use `Effect.Service` for standard services with sensible defaults
- Use `Context.Tag` for type-first design or contextual services
- Always specify globally unique identifiers (`@app/ServiceName`)
- Keep service interfaces focused and cohesive

### Service Implementation
- Access dependencies at the top of `Effect.gen` constructors
- Return service interface with `as const` for type safety
- Use `scoped` option for services managing resources
- Implement proper logging and tracing in service methods

### Layer Management
- Compose all layers once, provide once at application boundary
- Use `Layer.mergeAll` for combining multiple independent layers
- Use `Layer.scoped` for services needing resource cleanup
- Understand layer memoization guarantees

### Service Design
- Follow single responsibility principle
- Extract services only when needed (reuse, testing, multiple implementations)
- Use descriptive, namespace-qualified service names
- Design services with testing in mind

### Testing
- Create mock layers with `Layer.succeed` for unit tests
- Use shadow services for call tracking and assertions
- Write integration tests with real implementations
- Test service lifecycles and resource cleanup

### Architecture
- Follow layered architecture (Store → Usecase → Handler)
- Keep business logic in usecase layer
- Handle HTTP concerns in handler layer only
- Use co-located usecases for simple operations

### Lifecycle Management
- Use `Effect.acquireRelease` for resources needing cleanup
- Handle errors in cleanup gracefully (log but don't fail)
- Use `Effect.addFinalizer` for additional cleanup logic
- Test resource lifecycle and cleanup paths
