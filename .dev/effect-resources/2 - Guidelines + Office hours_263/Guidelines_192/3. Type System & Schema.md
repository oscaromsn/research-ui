## 3. Type System & Schema

### Core Principle

All data structures crossing boundaries (API inputs/outputs, database entities, external service messages, function arguments/returns) MUST be defined with `@effect/schema`. Schema provides runtime validation, compile-time types, and serialization/deserialization capabilities in a single, composable abstraction.

### 3.1 Schema Definition (@effect/schema)

#### Basic Schema Types

Effect Schema provides a comprehensive set of primitive and composite schema types:

```typescript
import * as S from "@effect/schema/Schema"

// Primitive types
const StringSchema = S.String
const NumberSchema = S.Number
const BooleanSchema = S.Boolean
const BigIntSchema = S.BigInt
const SymbolSchema = S.Symbol
const UndefinedSchema = S.Undefined
const NullSchema = S.Null
const UnknownSchema = S.Unknown

// Refined primitives
const UUIDSchema = S.UUID
const EmailSchema = S.String.pipe(S.pattern(/^[^\s@]+@[^\s@]+\.[^\s@]+$/))
const PositiveNumber = S.Number.pipe(S.positive())
const IntegerSchema = S.Number.pipe(S.int())
const NonEmptyString = S.String.pipe(S.nonEmpty())

// Composite types
const UserSchema = S.Struct({
  id: S.UUID,
  name: S.NonEmptyString,
  email: EmailSchema,
  age: S.Number.pipe(S.int(), S.greaterThanOrEqualTo(0))
})

const ArraySchema = S.Array(S.String)
const RecordSchema = S.Record({
  key: S.String,
  value: S.Number
})
const TupleSchema = S.Tuple(S.String, S.Number, S.Boolean)
```

#### Schema Patterns

**Nested Schemas:**

```typescript
// Define reusable schemas
const AddressSchema = S.Struct({
  street: S.String,
  city: S.String,
  state: S.String,
  zipCode: S.String.pipe(S.pattern(/^\d{5}(-\d{4})?$/))
})

const ContactSchema = S.Struct({
  email: EmailSchema,
  phone: S.String.pipe(S.pattern(/^\+?[\d\s-()]+$/))
})

// Compose into complex schemas
const PersonSchema = S.Struct({
  id: S.UUID,
  name: S.NonEmptyString,
  address: AddressSchema,
  contact: ContactSchema,
  dateOfBirth: S.Date
})

type Person = S.Schema.Type<typeof PersonSchema>
```

**Optional and Nullable Fields:**

```typescript
// Optional fields (may be undefined or omitted)
const UserProfileSchema = S.Struct({
  userId: S.UUID,
  bio: S.optional(S.String),
  website: S.optional(S.String),
  avatarUrl: S.optionalWith(S.String, {

// Nullable fields (explicitly null or value)
const ProductSchema = S.Struct({
  id: S.UUID,
  name: S.String,
  description: S.NullOr(S.String), // Can be null

// Combined: optional AND nullable

```

**Default Values:**

```typescript
const ConfigSchema = S.Struct({

// With context-aware defaults

  data: S.String,
```

**Schema Composition:**

```typescript

const BaseEntitySchema = S.Struct({

const UserEntitySchema = S.extend(
```

**Custom Refinements:**

```typescript
// Custom validation logic
const PasswordSchema = S.String.pipe(
  S.filter((password) => {
    const hasLowerCase = /[a-z]/.test(password)
    const hasUpperCase = /[A-Z]/.test(password)
    const hasNumber = /\d/.test(password)
    const hasSpecial = /[!@#$%^&*]/.test(password)
    const isLongEnough = password.length >= 8
    
    return hasLowerCase && hasUpperCase && hasNumber && hasSpecial && isLongEnough
  }, {
    message: () => "Password must be at least 8 characters and contain lowercase, uppercase, number, and special character"
  })
)

// Multiple custom validations
const AgeSchema = S.Number.pipe(
  S.int(),
  S.filter((age) => age >= 18, {
    message: () => "Must be at least 18 years old"
  }),
  S.filter((age) => age <= 120, {
    message: () => "Age must be realistic"
  })
)

// Dependent field validation
const RegistrationSchema = S.Struct({
  password: PasswordSchema,
  confirmPassword: S.String
}).pipe(
  S.filter((data) => data.password === data.confirmPassword, {
    message: () => "Passwords must match"
  })
)
```

#### Schema Transformations

**Basic Transformations:**

```typescript
// Transform string to Date
const DateFromString = S.String.pipe(
  S.transform(
    S.Date,
    {
      decode: (str) => new Date(str),
      encode: (date) => date.toISOString()
    }
  )
)

// Transform string to number
const NumberFromString = S.String.pipe(
  S.transform(
    S.Number,
    {
      decode: (str) => parseFloat(str),
      encode: (num) => num.toString()
    }
  )
)

// Case transformation
const LowerCaseString = S.String.pipe(
  S.transform(
    S.String,
    {
      decode: (str) => str.toLowerCase(),
      encode: (str) => str
    }
  )
)
```

**Effect-Based Transformations:**

```typescript
// TransformOrFail for operations that can fail
const ValidatedNumberFromString = S.String.pipe(
  S.transformOrFail(
    S.Number,
    {
      decode: (str, _, ast) => {
        const num = parseFloat(str)
        return isNaN(num)
          ? ParseResult.fail(new ParseResult.Type(ast, str))
          : ParseResult.succeed(num)
      },
      encode: (num) => ParseResult.succeed(num.toString())
    }
  )
)

// Complex transformation with Effect
const UserFromApiResponse = S.Unknown.pipe(
  S.transformOrFail(
    UserSchema,
    {
      decode: (input, _, ast) => {
        if (typeof input !== 'object' || input === null) {
          return ParseResult.fail(new ParseResult.Type(ast, input))
        }
        
        const data = input as any
        return ParseResult.succeed({
          id: data.user_id,
          name: data.full_name,
          email: data.email_address
        })
      },
      encode: (user) => ParseResult.succeed({
        user_id: user.id,
        full_name: user.name,
        email_address: user.email
      })
    }
  )
)
```

**Common Transformation Patterns:**

```typescript
// DateTime transformations
const DateTimeUtc = S.String.pipe(
  S.transform(
    S.Date,
    {
      decode: (str) => new Date(str),
      encode: (date) => date.toISOString()
    }
  )
)

const UnixTimestamp = S.Number.pipe(
  S.transform(
    S.Date,
    {
      decode: (timestamp) => new Date(timestamp * 1000),
      encode: (date) => Math.floor(date.getTime() / 1000)
    }
  )
)

// JSON string transformations
const JsonString = <A>(schema: S.Schema<A>) =>
  S.String.pipe(
    S.transformOrFail(
      schema,
      {
        decode: (str, options, ast) => {
          try {
            return ParseResult.succeed(JSON.parse(str))
          } catch (e) {
            return ParseResult.fail(new ParseResult.Type(ast, str))
          }
        },
        encode: (value) => ParseResult.succeed(JSON.stringify(value))
      }
    )
  )
```

### 3.2 Schema Classes

#### Schema.Class

Schema.Class provides an opaque type with automatic `Equal` and `Hash` implementations:

```typescript
import * as S from "@effect/schema/Schema"

// Basic class definition
class User extends S.Class<User>("User")({
  id: S.UUID,
  name: S.String,
  email: EmailSchema,
  createdAt: S.Date
}) {
  // Add methods to instances
  get displayName(): string {
    return `${this.name} (${this.email})`
  }
  
  isRecent(): boolean {
    const dayAgo = new Date(Date.now() - 24 * 60 * 60 * 1000)
    return this.createdAt > dayAgo
  }
}

// Constructor with validation
const user = new User({
  id: crypto.randomUUID(),
  name: "John Doe",
  email: "john@example.com",
  createdAt: new Date()
})

// Automatic structural equality
const user2 = new User({
  id: user.id,
  name: "John Doe",
  email: "john@example.com",
  createdAt: user.createdAt
})

console.log(Equal.equals(user, user2)) // true

// Disable validation for trusted sources
const userFromDb = new User(
  dbRow,
  { disableValidation: true } // Skip validation when data is already trusted
)
```

#### Schema.TaggedClass

Schema.TaggedClass adds a `_tag` discriminator field for better type discrimination:

```typescript
// Tagged class with discriminator
class Product extends S.TaggedClass<Product>()("Product", {
  id: S.UUID,
  name: S.String,
  price: S.Number.pipe(S.positive()),
  category: S.String
}) {
  get priceWithTax(): number {
    return this.price * 1.1
  }
}

class Service extends S.TaggedClass<Service>()("Service", {
  id: S.UUID,
  name: S.String,
  hourlyRate: S.Number.pipe(S.positive()),
  category: S.String
}) {
  estimateCost(hours: number): number {
    return this.hourlyRate * hours
  }
}

// Union type with automatic discrimination
type Item = Product | Service

const processItem = (item: Item) => {
  switch (item._tag) {
    case "Product":
      // TypeScript knows this is Product
      return item.priceWithTax
    case "Service":
      // TypeScript knows this is Service
      return item.estimateCost(1)
  }
}
```

#### Model from @effect/sql

Model.Class provides specialized schemas for database entities with multiple derived schemas:

```typescript
import { Model } from "@effect/sql"
import * as S from "@effect/schema/Schema"

class User extends Model.Class<User>("User")({
  id: Model.Generated(S.UUID), // Auto-generated field
  firstName: S.NonEmptyString,
  lastName: S.NonEmptyString,
  email: EmailSchema,
  dateOfBirth: Model.FieldOption(Model.Date), // Optional Date field
  isActive: S.Boolean.pipe(S.withDefault(() => true)),
  createdAt: Model.DateTimeInsert, // Set on insert
  updatedAt: Model.DateTimeUpdate  // Set on insert/update
}) {}

// Different schemas for different use cases:

// 1. Full entity (database representation)
type UserEntity = typeof User.Type
// Has all fields including id, createdAt, updatedAt

// 2. Insert schema (for database INSERT)
type UserInsert = typeof User.insert.Type
// Omits Generated fields (id) and DateTimeInsert/Update fields

// 3. Update schema (for database UPDATE)
type UserUpdate = typeof User.update.Type
// Requires id, optional other fields, updates DateTimeUpdate

// 4. JSON schema (client-facing)
type UserJson = typeof User.json.Type
// Serialized form for API responses

// 5. JSON create (client insert data)
type UserJsonCreate = typeof User.jsonCreate.Type
// Client data for creating users

// 6. JSON update (client update data)
type UserJsonUpdate = typeof User.jsonUpdate.Type
// Client data for updating users

// Usage with database operations
const createUser = (data: UserInsert) =>
  Effect.gen(function* () {
    const db = yield* Database
    const result = yield* db.query(
      S.decodeUnknown(User.insert)(data)
    )
    return result
  })

const updateUser = (data: UserUpdate) =>
  Effect.gen(function* () {
    const db = yield* Database
    const result = yield* db.query(
      S.decodeUnknown(User.update)(data)
    )
    return result
  })
```

### 3.3 Branded Types

#### Creating Branded Types

Branded types provide nominal typing in TypeScript's structural type system:

```typescript
import * as S from "@effect/schema/Schema"

// Create branded type
const UserId = S.UUID.pipe(S.brand("UserId"))
type UserId = S.Schema.Type<typeof UserId>

const ProjectId = S.String.pipe(
  S.pattern(/^proj_[a-z0-9]{16}$/),
  S.brand("ProjectId")
)
type ProjectId = S.Schema.Type<typeof ProjectId>

// More complex branded types
const PositiveInteger = S.Number.pipe(
  S.int(),
  S.positive(),
  S.brand("PositiveInteger")
)
type PositiveInteger = S.Schema.Type<typeof PositiveInteger>

const EmailAddress = S.String.pipe(
  S.pattern(/^[^\s@]+@[^\s@]+\.[^\s@]+$/),
  S.brand("EmailAddress")
)
type EmailAddress = S.Schema.Type<typeof EmailAddress>

// Custom validation with branding
const KeyHash = S.String.pipe(
  S.length(56),
  S.pattern(/^[0-9a-f]{56}$/),
  S.brand("KeyHash")
)
type KeyHash = S.Schema.Type<typeof KeyHash>
```

```typescript
const createUserCache = () =>
```

### 3.4 Schema Validation Patterns

#### Decoding External Input

**Basic Decoding:**

```typescript
import * as S from "@effect/schema/Schema"
import { Effect } from "effect"

// Decode unknown data (returns Effect)
const validateUser = (input: unknown): Effect.Effect<User, S.ParseError> =>
  S.decodeUnknown(UserSchema)(input)

// Decode with known input type
const validateUserData = (input: UserInput): Effect.Effect<User, S.ParseError> =>
  S.decode(UserSchema)(input)

// Synchronous decode (throws on error)
const validateUserSync = (input: unknown): User =>
  S.decodeSync(UserSchema)(input)

// Parse (alias for decode)
const parseUser = (input: unknown): Effect.Effect<User, S.ParseError> =>
  S.parse(UserSchema)(input)
```

**API Input Validation:**

```typescript
// HTTP request validation
const validateCreateUserRequest = (body: unknown) =>
  Effect.gen(function* () {
    const validated = yield* S.decodeUnknown(CreateUserSchema)(body)
    
    // Additional business validations
    const emailExists = yield* checkEmailExists(validated.email)
    if (emailExists) {
      return yield* Effect.fail(new EmailAlreadyExistsError())
    }
    
    return validated
  })

// Query parameter validation
const QueryParamsSchema = S.Struct({
  page: S.NumberFromString.pipe(S.int(), S.positive()),
  pageSize: S.NumberFromString.pipe(S.int(), S.positive(), S.lessThanOrEqualTo(100)),
  sortBy: S.optional(S.Literal("name", "createdAt", "updatedAt")),
  sortOrder: S.optional(S.Literal("asc", "desc"))
})

const validateQueryParams = (params: unknown) =>
  S.decodeUnknown(QueryParamsSchema)(params)
```

**Database Input Validation:**

```typescript
// Validate before database operations
const createUser = (input: unknown) =>
  Effect.gen(function* () {
    const db = yield* Database
    
    // Validate against insert schema
```

#### Schema at Boundaries

**Application Boundaries:**

```typescript
// API boundaries
class UserApi extends Effect.Service<UserApi>()(
  "UserApi",
  {
    effect: Effect.gen(function* () {
      const service = yield* UserService
      
      return {
        // Validate input, return validated output

          Effect.gen(function* () {
            const validated = yield* S.decodeUnknown(CreateUserSchema)(input)

            return yield* S.encode(PublicUserSchema)(user)
          }),
        
        // Validate parameters
        getUser: (id: unknown) =>
          Effect.gen(function* () {
            const userId = yield* S.decodeUnknown(UserId)(id)
            const user = yield* service.getUser(userId)
            return yield* S.encode(PublicUserSchema)(user)
          })
      } as const
    })
  }
) {}

// Message queue boundaries
const processMessage = (message: unknown) =>
  Effect.gen(function* () {
    // Validate incoming message
    const validated = yield* S.decodeUnknown(MessageSchema)(message)
    
    // Process
    const result = yield* handleMessage(validated)
    
    // Encode outgoing message
    return yield* S.encode(ResultMessageSchema)(result)
  })

// External service boundaries
class ExternalApiClient extends Effect.Service<ExternalApiClient>()(

  {

            const response = yield* http.get(`/api/data/${id}`)

            const validated = yield* S.decodeUnknown(ExternalDataSchema)(
              response.body
            )
            
            return validated
          })
      } as const
    })
  }
) {}
```

### 3.5 Union Types & Discriminated Unions

#### Simple Unions

```typescript
// Basic union
const StringOrNumber = S.Union(S.String, S.Number)
type StringOrNumber = S.Schema.Type<typeof StringOrNumber>

// Multiple types
const MultiType = S.Union(
  S.String,
  S.Number,
  S.Boolean,
  S.Null
)

// Optional with union
const OptionalString = S.Union(S.String, S.Undefined)
// Or more idiomatically:
```

#### Discriminated Unions

**Basic Discriminated Union:**

```typescript
// Define variants with _tag discriminator
const Success = S.Struct({
  _tag: S.Literal("Success"),
  value: S.Number
})

const Failure = S.Struct({
  _tag: S.Literal("Failure"),
  error: S.String
})

const Result = S.Union(Success, Failure)
type Result = S.Schema.Type<typeof Result>

// Pattern matching with exhaustive checking
const processResult = (result: Result): string => {
  switch (result._tag) {
    case "Success":
      return `Success: ${result.value}`
    case "Failure":
      return `Error: ${result.error}`
  }
}
```

**Complex Discriminated Union:**

```typescript
// Payment method variants
const CreditCard = S.Struct({
  type: S.Literal("credit_card"),
  cardNumber: S.String,
  expiryDate: S.String,
  cvv: S.String
})

const PayPal = S.Struct({
  type: S.Literal("paypal"),
  email: EmailSchema
})

const BankTransfer = S.Struct({
  type: S.Literal("bank_transfer"),
  accountNumber: S.String,
  routingNumber: S.String,
  bankName: S.String
})

const PaymentMethod = S.Union(CreditCard, PayPal, BankTransfer)

const processPayment = (method: PaymentMethod) => {
  switch (method.type) {
    case "credit_card":
      // TypeScript knows: method.cardNumber exists
      return processCreditCard(method)
    case "paypal":
      // TypeScript knows: method.email exists
      return processPayPal(method)
    case "bank_transfer":
      // TypeScript knows: method.accountNumber exists
      return processBankTransfer(method)
  }
}
```

### 3.6 Type Annotations

#### When to Annotate

**Public API Boundaries (MANDATORY):**

```typescript
// ✅ Annotate exported functions
export const createUser = (
  input: CreateUserInput
): Effect.Effect<User, CreateUserError, Database> =>
  Effect.gen(function* () {
    const db = yield* Database
    // Implementation...
  })

// ✅ Annotate service interfaces
interface UserService {
  readonly getUser: (id: UserId) => Effect.Effect<User, UserNotFoundError>
  readonly createUser: (input: CreateUserInput) => Effect.Effect<User, CreateUserError>
  readonly deleteUser: (id: UserId) => Effect.Effect<void, UserNotFoundError>
}
```

**Complex Inference Failures:**

```typescript
// ✅ Annotate when inference fails
const complexOperation = <A, E, R>(
  effect: Effect.Effect<A, E, R>
): Effect.Effect<A[], E, R> => // Explicit return type needed
  Effect.all([effect, effect, effect])

// ✅ Annotate intermediate complex types
const processData = (data: Data[]) => {
  const grouped: Map<string, Data[]> = new Map() // Explicit type helps
  
  for (const item of data) {
    const key = item.category
    const items = grouped.get(key) ?? []
    items.push(item)
    grouped.set(key, items)
  }
  
  return grouped
}
```

**Documentation Clarity:**

```typescript
// ✅ Annotate for better IntelliSense
export interface DatabaseConfig {
  readonly host: string
  readonly port: number
  readonly database: string
  readonly maxConnections: number
}

// ✅ Clear Effect signatures
export const connectToDatabase = (
  config: DatabaseConfig
): Effect.Effect<Database, DatabaseError, never> =>
  Effect.gen(function* () {
    // Implementation...
  })
```

#### Type Inference Preference

**Let TypeScript Infer When Possible:**

```typescript
// ✅ Good: Let inference work
const getUserProfile = (id: UserId) =>
  Effect.gen(function* () {
    const user = yield* userService.getUser(id)      // User inferred
    const posts = yield* postService.getUserPosts(id) // Post[] inferred
    return { user, posts }                             // Return type inferred
  })

// ❌ Avoid: Over-annotation
const getUserProfile = (id: UserId): Effect.Effect
  { user: User; posts: Post[] },
  UserNotFoundError | DatabaseError,
  UserService | PostService
> =>
  Effect.gen(function* () {
    const user: User = yield* userService.getUser(id)
    const posts: Post[] = yield* postService.getUserPosts(id)
    return { user, posts }
  })
```

**Generator Type Inference:**

```typescript
// ✅ Generator functions infer types automatically
const pipeline = Effect.gen(function* () {
  const step1 = yield* firstStep()    // Type inferred from firstStep return
  const step2 = yield* secondStep(step1) // Type inferred from secondStep return
  const step3 = yield* thirdStep(step2)  // Type inferred from thirdStep return
  return step3                            // Return type inferred
})
```

**When Inference Fails:**

```typescript
// Complex generic scenarios may need help
const processItems = <T>(
  items: T[],
  process: (item: T) => Effect.Effect<T, Error>
): Effect.Effect<T[], Error> => // Explicit return type needed for clarity
  Effect.all(items.map(process))

// Conditional types may need annotation
const conditional = <A>(
  condition: boolean,
  ifTrue: Effect.Effect<A>,
  ifFalse: Effect.Effect<A>
): Effect.Effect<A> => // Annotation helpful
  condition ? ifTrue : ifFalse
```

#### Type vs Interface

**Use `type` for Unions:**

```typescript
// ✅ Use type for union types
type Status = "pending" | "active" | "completed" | "failed"

type Result<T, E> = 
  | { _tag: "Success"; value: T }
  | { _tag: "Failure"; error: E }

type UserRole = "admin" | "user" | "guest"

type ErrorType = ValidationError | DatabaseError | NetworkError
```

**Use `interface` for Opaque Types:**

```typescript
// ✅ Use interface for service definitions
interface UserService {
  readonly getUser: (id: UserId) => Effect.Effect<User, UserNotFoundError>
  readonly createUser: (data: CreateUserData) => Effect.Effect<User, CreateUserError>
  readonly updateUser: (id: UserId, data: UpdateUserData) => Effect.Effect<User, UpdateUserError>
  readonly deleteUser: (id: UserId) => Effect.Effect<void, UserNotFoundError>
}

// ✅ Use interface for repository patterns
interface Repository<T, Id> {
  readonly findById: (id: Id) => Effect.Effect<T, NotFoundError>
  readonly save: (entity: T) => Effect.Effect<T, SaveError>
  readonly delete: (id: Id) => Effect.Effect<void, NotFoundError>
}
```

**Function Signatures:**

```typescript
// ✅ Use type for function signatures
type TransformFn<A, B> = (input: A) => Effect.Effect<B, Error>

type ValidatorFn<T> = (value: T) => Effect.Effect<T, ValidationError>

type ProcessorFn<In, Out> = (input: In) => Effect.Effect<Out, ProcessError>

// ✅ Use interface for callable objects with properties
interface Logger {
  readonly info: (message: string) => Effect.Effect<void>
  readonly error: (message: string, error?: unknown) => Effect.Effect<void>
  readonly warn: (message: string) => Effect.Effect<void>
  readonly debug: (message: string) => Effect.Effect<void>
  readonly level: LogLevel
  readonly context: Record<string, unknown>
}
```

### Best Practices Summary

1. **Always Validate Boundaries**: Use Schema at API, database, and external service boundaries
2. **Branded Types**: Use for domain-specific identifiers to prevent type mixing
3. **Discriminated Unions**: Prefer _tag field for better type narrowing and error messages
4. **Schema Composition**: Build complex schemas from simple, reusable pieces
5. **Type Inference**: Let TypeScript infer types; annotate only when necessary
6. **Documentation**: Add titles, descriptions, and examples to schemas
7. **Error Messages**: Provide clear, actionable validation error messages
8. **Schema.Class**: Use for domain entities with methods
9. **Model.Class**: Use for database entities with generated fields
10. **Test Schemas**: Write tests for edge cases and validation rules
